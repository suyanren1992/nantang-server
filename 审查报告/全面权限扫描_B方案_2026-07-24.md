## 🔴 Critical（立即修复）

### CR-1 · CORS 通配符 + allow_credentials → 跨站请求伪造
- **位置**：[server/main.py:63](server/main.py#L63)
- **问题**：`allow_origins` 包含 `https://*.trycloudflare.com` 和 `https://*.pages.dev`，同时 `allow_credentials=True`
- **攻击路径**：攻击者注册免费 `attacker.trycloudflare.com` 子域名，部署 fetch 请求携带受害者 cookie → 以受害者身份执行转账/提现
- **修法**：移除通配符域名，改用环境变量注入精确 origin 白名单

### CR-2 · 注册 invite_code 被服务端静默丢弃
- **位置**：[api.js:65](nantang-mobile/js/api.js#L65) → [auth.py:15](server/routes/auth.py#L15)
- **问题**：前端 POST `/api/auth/register` 发送 `{name, password, role, avatar_seed, invite_code}`，但服务端 `RegisterRequest` 模型没有 `invite_code` 字段 → 被 pydantic 静默丢弃
- **影响**：任何人无需有效邀请码即可注册，整个邀请制在后端形同虚设
- **修法**：`RegisterRequest` 加 `invite_code: str = ''`，register 端点中验证并消费邀请码

## 🟠 High（优先修复）

### H-1 · 用户名 LIKE 通配符注入 — `%` 账号看全量数据
- **位置**：[nt.py:99](server/routes/nt.py#L99)、:402、[tasks.py:64](server/routes/tasks.py#L64)
- **问题**：注册端点仅校验用户名长度（1-64），无字符白名单。用户可注册名为 `%` 的账号。三处 LIKE 查询 `f'%"{user.id}"%'` 被 `%` 注入为 `%"%"%` → 匹配所有有认领者的行
- **影响**：可查看全平台任务列表、流水记录
- **修法**：注册加正则 `/^[a-zA-Z0-9_一-龥]+$/`，或 LIKE 中转义 `%` 和 `_`

### H-2 · 提现余额检查无行锁 — 并发双重扣款
- **位置**：[nt.py:339](server/routes/nt.py#L339)
- **问题**：`withdraw` 端点的 user 来自 `get_current_user` 依赖注入（查询未用 `with_for_update`）。余额检查和扣款均在未加锁对象上。两个并发提现可同时通过检查 → 各自扣款 → 余额变负
- **修法**：余额检查前重新查询并加行锁：`select(User).where(User.id == user.id).with_for_update()`

### H-3 · Cashout 端点无行锁 — 并发扣款下溢
- **位置**：[nt.py:313](server/routes/nt.py#L313)
- **问题**：同上模式，管理员 cashout 未对 target 用户和 CommunityPool 使用 `with_for_update`
- **修法**：target 查询加 `with_for_update()`，pool 查询改为 `_get_pool(db, lock=True)`

### H-4 · 新手引导崩溃：`newbieQuests` 格式冲突
- **位置**：[app.js:236](nantang-mobile/js/app.js#L236) / [data.js:59](nantang-mobile/js/data.js#L59)
- **问题**：`newbieQuests` 在 data.js 中定义为对象 map（`{q1:{...}, q2:{...}}`），但 app.js 的 `_completeNewbieQuest` 按数组 `.find()` 访问 → 类型不匹配必崩溃
- **影响**：新手引导完全不可用
- **修法**：统一数据格式（建议转为数组），`_completeNewbieQuest` 适配

### H-5 · `_growDirtiness` 导致脏污度 NaN
- **位置**：[app.js:2067](nantang-mobile/js/app.js#L2067)
- **问题**：旧数据空间脏污度字段缺失时，数学运算产生 NaN，扩散到整个打扫系统
- **影响**：打扫系统完全失效（脏污度显示异常、定价错误）
- **修法**：加 `|| 0` 兜底

### H-6 · `showConfirm` 乱码：`encodeURIComponent` 误用于 HTML
- **位置**：[data.js:514](nantang-mobile/js/data.js#L514)
- **问题**：`encodeURIComponent` 将中文编码为 `%E5%BC%A0%E4%B8%89`，应使用 `esc()`（HTML 实体转义）
- **影响**：所有确认对话框中文名显示为 `%XX%XX` 乱码，用户无法理解确认内容
- **修法**：`encodeURIComponent` → `esc()`

### H-7 · 任务状态变更每次都触发 400 静默失败
- **位置**：[app-data.js:138](nantang-mobile/js/app-data.js#L138) → [tasks.py:142](server/routes/tasks.py#L142)
- **问题**：`AppData.updateTask()` 调用 `API.syncTaskUpdate()` 发送 `{status, ...}`，但服务端 `TaskUpdate` 模型显式拒绝 status 字段（返回 400 "状态请通过专用端点变更"）
- **影响**：每次任务状态流转额外产生一次必然失败的 HTTP 请求，浪费带宽且无用户感知
- **修法**：`syncTaskUpdate` 中若 updates 含 status 则跳过直接 resolve

### H-8 · sync_shared 混合 camelCase/snake_case — 计时炸弹
- **位置**：[app-data.js:226](nantang-mobile/js/app-data.js#L226) / [data.py:387](server/routes/data.py#L387)
- **问题**：同一请求体内 `map_locations`（snake）和 `canteenMenu`（camel）混用。目前两端错成一样故能通，但任何一方按规范统一都会断裂
- **修法**：统一 snake_case

### H-9 · 村口页面小屏裁剪
- **位置**：[main.css:100](nantang-mobile/css/main.css#L100)
- **问题**：`.village-group` position:fixed top:200px + `.village-window` 340px = 固定 540px。iPhone SE（320×568）可视区仅约 500px，村口三卡底部被裁切
- **修法**：改用相对定位或 calc(100vh - 头部高度)
