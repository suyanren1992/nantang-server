## 二、下辖节一：编码规范（南塘三盲区 · 教程没教、实战咬过）

> K-1 裁定①：三盲区规范并入本页一节，不新建 Schema 散文件（一门 + YAGNI）。
> 适用：所有施工卡；验收时异体关按此节对照。

### 2.1 异步行锁 🔴

- **病灶**：SQLite 下 `with_for_update()` 静默失效（SQLAlchemy 官方文档证实）——
  D-5/D-17/D-26 锁路径在本地测试过≠线上 PG 真锁。
- **规范**：① 资金/权限写路径必加 `with_for_update()`，且加锁后重读关联对象
  （`populate_existing` 教训，D-5）；② 多锁路径注意锁序（AB-BA 死锁，D-5 观察④）；
  ③ 锁有效性不以 SQLite 测试为凭——真 PG 锁测试见 K-2 卡。

### 2.2 幂等

- **病灶**：重试/双击/离线队列会重复提交——A-7 实例：客户端带 id 优先按 id 幂等。
- **规范**：① 资金/状态变更端点必设幂等键（客户端 id 或业务唯一键），重复提交返回原结果；
  ② 周期任务按周期幂等（D-26 日扣：`last_deducted` 起算、逐日独立 ledger，补扣到天不重复）；
  ③ 「改资金/权限端点的触发源、调用方、幂等键」= 宪法级改动，走铁律 9 三视角。

### 2.3 跨端命名

- **病灶**：同一字段前后端两名（如 `presence` 三值口径、多签 `camp_multisig` 仅概念引用），
  文档与代码对不上账。
- **规范**：① 跨端字段名/枚举值以前端-服务端**同一拼写**为准，改一端必查另一端
  （`grep` 全仓库，不只搜你以为它在的文件——DB-1 打回教训）；
  ② 真源文档（法源指针表末行）的每个 `文件:行号` 引用 = 可证伪承诺，按 §三.2 机检交付。

## 三、下辖节二：审查 SOP（谏臣席 + 真源文档交付闸）

> K-1 裁定②：审计三步法 = 谏臣席标准 SOP，随本页落位。

### 3.1 审计三步法（谏臣席 SOP）

1. **逐条排查**（补课 27）：审计对象逐条过，不抽样代替全量；
2. **闭环保真**（补课 26）：结论与证据一一对应，无证据不入报告；
3. **看实证**（补课 17）：不听「做完了/不存在」——`grep` 全仓库实证才算数；
   否定性断言（X 不存在）比肯定性断言更需要实证（DB-1 关⑤打回教训）。

### 3.2 真源文档引证全量机检（2026-07-26 新立 · 砚仁批「可以」）

- **规范**：真源文档（§一末行五份）交付前，全文 `文件:行号` 引用**全量机检**——
  脚本逐条拉出被引代码行，逐条判定「陈述与代码相符/不符」，**全符才算交付**。
  抽样验收不再视为充分（DB-1：三营三轮抽样均漏，一处事实错误打回）。
- 脚本为一次性纯 stdlib 小工具（≤40 行），验收方自写自用，不归模型席位（lint 纯脚本先例）。

## 四、月度机制

### 4.1 安全复核（D-23 基线）

- 模板：`方案/任务卡/模板_月度安全复核.md`；扫描器：`server/scripts/security_scan.py`；
  密钥清单随模板。每月跑一次，结果入当月 Daily + BUG_TRACKER。

### 4.2 拟票执行跟踪（K-1 裁定③补充条款）

- 每月安全复核时，附带核对**当月砚仁批准的拟票/裁定是否已落盘**
  （文档落位/卡发出/条款同步三项），未落盘项列清单呈砚仁——防「批了没人办」。

### 4.3 宪法核心条款入场令同步

- 每次宪法级条款变动（铁律增删/编码规范节修订），**同卡**把核心条款同步进
  `CLAUDE.md` + `AGENTS.md`——入场令与宪法不一致 = 两营按旧法施工。
- 本次同步（v0.1）：两文件已追加「宪法汇编页指针 + 编码规范三条 + 引证全量机检 + 太傅注」。
