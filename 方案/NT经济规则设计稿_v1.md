# NT 经济规则设计稿 v1

> **性质**：规则提取，非规则创制。把代码里已经在跑的 NT 经济逻辑翻译成人话，供砚仁一次看清全貌、裁定修改。
> **数据基准**：2026-07-29，commit `dcd17fa`（M-2b 出闸后）。
> **适用范围**：社区场地方池 + 营地活动方池，NT 同一种货币。

---

## 一、三轨体系：每一笔劳动记三个数

| 轨道 | 名称 | 干什么用 | 怎么获得 |
|------|------|----------|----------|
| **NT**（南塘币） | 流通货币 | 花——付住宿费、订餐、打赏、买东西 | 做任务、被卡片猜中、校核通过、池发奖 |
| **CV**（贡献值） | 信誉积分 | 攒——决定权限等级、解锁能力 | 做任务累积；转账时随 NT 一起转（75% 给接收方，25% 入公共池） |
| **XP**（经验值） | 劳动累积 | 升——解锁称号（园丁/修理工/厨神） | 做任务、池发奖时同步记 |

**关键规则**：
- NT 可花可转，CV 和 XP 只涨不花（不可直接消费）
- CV 首次注册冻结 75 点，完成 5 步新手任务逐步解冻（每步 15 CV）
- 信誉分（trust_score）独立于 CV，初始 100，范围 0-100，影响提现权限和角色等级

## 二、资金池架构：万达广场与店铺

> 两池独立核算，NT 是同一种货币。关系 = 万达广场（场地方）与店铺（商户）。

### 社区场地方池（CommunityPool）

| 子池 | 用途 | 来源 |
|------|------|------|
| **运营池** `balance` | 日常发放（任务奖、卡片奖、校核奖） | 充值、topup、spend 回流、盈余<1000 时留存 |
| **任务托管** `task_escrow` | 发布任务时冻结的赏金 | 发布任务扣 user→escrow；审核/取消/仲裁释放 |
| **储备池** `reserve` | 战略储备，提现资金来源 | 链上充值、运营池>1000 时盈余划拨 |
| **冻结池** `frozen` | 提现等待期锁定 | 用户申请提现→从 reserve 转入 frozen |
| **营队池** `camp_balance` | 营地活动独立收支 | 创营注资、营地任务支付 |

### 会计等式（铁律）

```
total_issued = 所有用户余额之和 + 运营池 + 托管 + 储备 + 冻结 + 营队池
```

**任何时刻都必须成立。** 差 1 NT 都是 bug。`GET /api/nt/verify` 可实时校验。

## 三、收入路径：NT 从哪来

### 3.1 做任务（F2）

| 环节 | 资金流向 | 说明 |
|------|----------|------|
| 发布 | 发布者余额 → 任务托管 | `reward × slots` 冻结 |
| 审核通过 | 托管 → 每个执行者 | 每人得 `reward`，同时 +CV +XP |
| 部分领取 | 未领份额 → 发布者 | `(slots - 实领人数) × reward` 退还 |
| 3 次退回 | 托管 → 发布者 | 自动取消，全额退回 |
| 取消任务 | 托管 → 发布者 | 全额退还 |

**营地任务**（scope=camp）：从 `camp_balance` 支付，其余规则相同。

### 3.2 卡片室发现（F5）

| 环节 | 资金流向 | 说明 |
|------|----------|------|
| 发现确认 | 社区池 → 做事者 | 金额取自记录（`nt_doer`），不信客户端 |
| 猜中奖励 | 社区池 → 发现者 | `nt_guesser`（默认 5 NT） |

**四道防线**：
1. 发现者不能确认自己发起的发现（禁自校核 → 403）
2. 金额/收款方均从服务端记录取，不信客户端传参
3. 发现记录行锁（防并发双确认双发）
4. 发奖 + 状态变更同事务提交

### 3.3 校核通过（Verification）

| 环节 | 资金流向 | 说明 |
|------|----------|------|
| 校核通过 | 社区池 → 做事者 + 校核人 | 做事者得 `nt_amount`，校核人得 `verifier_reward` |

**防滥用**：同一对 1 小时冷却 + 日上限 10 次。

### 3.4 池发奖（admin 手动闸）

| 端点 | 调用方 | 说明 |
|------|--------|------|
| `POST /api/nt/earn` | 仅 admin | 社区池 → 指定用户，单笔上限 10000 NT |
| `POST /api/nt/card-confirm` | 村民（登录后） | 卡片确认发奖，服务端校验后内部调 `_grant_from_pool` |

两端点共用 `_grant_from_pool` 单闸内核：锁池 → 校验 → 扣池加人 → 写账本。

### 3.5 周期任务自动生成（F20）

每日 00:05 cron 触发 → 读 `periodic_tasks.json` 模板 → 检查幂等 → 社区池扣款 → 创建 NTTask（escrow 冻结）。

4 个模板：日常清扫 / 每周大扫除 / 每周盘点 / 日常堆肥。

### 3.6 充值（链上 / 手动）

| 方式 | 说明 |
|------|------|
| 链上充值 | 用户转 NT 到平台多签钱包 → `chain_scanner.py` 监听 → 自动到账 |
| 充值意向 | 用户创建意向 → 系统返回平台钱包地址 → 用户转账 → 链扫确认 |
| 手动 topup | admin 调用 `POST /api/nt/topup`，`total_issued` 增加 |
| 社区池注资 | `POST /api/nt/topup`，`user="community_pool"`，只增 `balance` 和 `total_issued` |

### 3.7 转账（user → user）

`POST /api/nt/transfer`，单笔上限 10000 NT。

**CV 流转规则**：转出方 CV 减少（转出额和现有 CV 取小值），其中 75% 给接收方，25% 入公共贡献池。

## 四、支出路径：NT 花到哪去

### 4.1 住宿费（F4 / F16）

**G-3 accrual 日记账模式**（默认）：
- 每日 00:05 cron 按房费率累加 `accommodation_due`（不动余额）
- 退房时一次性结算：够则扣 NT，不足记欠费（debt）

**deduct 日扣模式**（可回滚）：
- 设环境变量 `ACCOMMODATION_DAILY_MODE=deduct` 即切回
- 每日直接扣余额，不够记欠费

**房费率**（BED_RATES）：

| 房间 | A(dorm101) | B(dorm102) | C(dorm103) | D(dorm104) | E(dorm105) | F(dorm106) |
|------|-----------|-----------|-----------|-----------|-----------|-----------|
| NT/晚 | 20 | 30 | 30 | 60 | 30 | 35 |

### 4.2 食堂订餐（F15）

10 NT/餐，预定扣款，取消退款。截止时间后锁死。

### 4.3 消费（spend）

`POST /api/nt/spend`，scope 可选 personal（回流运营池）或 camp（回流营队池）。

### 4.4 提现（两阶段冻结）

| 阶段 | 操作 | 资金流向 |
|------|------|----------|
| 申请 | `POST /api/nt/withdraw` | 用户余额 → frozen 池，reserve 等额扣减 |
| 确认 | admin `/api/admin/withdraw/confirm` | frozen → 链上转账 |
| 驳回 | admin `/api/admin/withdraw/reject` | frozen → 退回用户余额 |

**提现门槛**：余额 ≥ 50 NT 且 ≤ 200 NT，信誉分 ≥ 60，7 天冷却期。

### 4.5 夸奖赞誉

| 档位 | NT | 说明 |
|------|-----|------|
| 👏 免费口头 | 0 | 不花 NT |
| 🌹 付费档 | 1 | 走 transfer 通道 |
| 🎁 重奖档 | 5 | 走 transfer 通道 |

### 4.6 茶馆八卦（半成品）

5 NT/条，走营地活动池。数据结构已预留，UI 未施工。

## 五、每日自动化（cron 00:05）

| 步骤 | 操作 | 条件 |
|------|------|------|
| 1 | 生成周期任务 | 读模板 → 幂等检查 → 池余额够 → 扣池建任务 |
| 2 | 住宿费记账/扣款 | 遍历活跃入住 → 按房费率逐日补扣 |
| 3 | 社区池补填 | 运营池 < 300 → 自动补 20 NT（增 total_issued） |
| 4 | 盈余划拨 | 运营池 > 1000 → 超出 500 的部分转入储备池 |
| 5 | 自动调水 | 运营池 < 150 且储备池 > 0 → 从储备池补到 300 |

**幂等**：`pool.last_tick_date == today` 直接跳过，不重复执行。

## 六、安全防线

### 涉钱操作四道通用防线

| # | 防线 | 实现 |
|---|------|------|
| 1 | 行级锁 | `with_for_update() + populate_existing`，防并发双花 |
| 2 | 金额服务端取 | 不信客户端传参，从数据库记录取金额 |
| 3 | 同事务提交 | 发奖 + 业务状态变更在同一事务内，原子操作 |
| 4 | 会计等式守恒 | `total_issued` = 全系统总和，`/api/nt/verify` 实时校验 |

### 权限门控

| 操作 | 权限要求 |
|------|----------|
| 转账/消费/提现申请 | 登录即可（`get_current_user`） |
| 池发奖 earn | 仅 admin（`require_admin`） |
| 卡片确认 card-confirm | 登录即可，但发现者不能确认自己的发现 |
| 手动 topup/cashout | 仅 admin |
| 提现确认/驳回 | 仅 admin |
| 校核审批 | 登录即可，但不能校核自己 |

### 提现额外防线

- 信誉分 ≥ 60
- 7 天冷却期（7 天内只能提一次）
- 单笔 50-200 NT
- 储备池余额需够支付

## 七、与公约的对接

> 公约是定价的唯一来源。平台跟随公约配置，不超线下约定。

| 公约条目 | 平台落地 | 当前状态 |
|----------|----------|----------|
| 校核奖励 15% | `verifier_reward_pct` | 需从 25% 改为 15%（C1） |
| 住宿价目 A-F | `BED_RATES` | 已一致 |
| 劳动价目 L1-L4 | `labor_pricing`（45 项） | 需逐项比对（C9） |
| 签署公约发 10 NT | covenant 签署流程 | 待施工（F1） |
| 岗位津贴 1500 NT/月 | 尚无配置 | 待施工（C6） |
| 每周一 15:00 大扫除 | 周期任务模板 | 需改配置（C7） |
