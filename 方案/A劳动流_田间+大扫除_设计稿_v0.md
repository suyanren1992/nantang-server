## 二、A 劳动流 · 五步统一流程（每页都这样拼）

```
[1.对象选择] → [2.动作选择] → [3.提交] → [4.校核] → [5.结算]
```

| 步 | 组件 | 数据 |
|---|---|---|
| 1 对象 | 地图/网格/卡片（依场景） | `MapLocation` / `Room` / `Field` |
| 2 动作 | 动作卡 + 价签 | 服务端定价单一真源（详见三） |
| 3 提交 | 按钮-主 | `POST /api/data/verifications`（服务端统一入口） |
| 4 校核 | 模态-居中（校核人视角） | 校核人调 `/verifications/{id}/approve|reject` |
| 5 结算 | toast + 活动流更新 | 单一真源定价，**服务端校验** `nt_amount ∈ 合理范围` |

## 三、改造点（涉钱 · 列皇帝御笔）

> 以下三件**必须**落地方可验收，缺一不可。

### 3.1 服务端定价单一真源（治 4+3 套分裂）

**现状**（W6-RECON）：
- 田间：4 套定价表（`farming_pricing` 5NT vs `labor_pricing` 15NT vs `_harvestCrop` 硬编 15NT vs …）
- 大扫除：3 套（`cleaning_pricing` / `nt_rewards` / `periodic_tasks`），按脏污等级（红→20/黄→15/绿→5）

**改造**：在 `server/routes/data.py` 建**单一真源表** `LABOR_PRICING`（dict 硬编起步，可后置配置）：
```python
# 田间（按动作类型）
LABOR_PRICING = {
    "weed": 10,        # 除草（统一为 10NT，吸收 5/15 分裂）
    "water": 8,        # 浇水
    "fertilize": 12,   # 施肥
    "harvest": 15,     # 收割（吸收硬编 15）
    # 大扫除（按脏污等级）
    "clean_red": 20,   # 脏污红
    "clean_yellow": 15,
    "clean_green": 5,
}
```

**前端禁用**任何本地定价表——全部从服务端拉（新增 `GET /api/labor/pricing`）。

### 3.2 服务端定价校验（治"客户端自传 nt_amount"）

**现状**（W6-RECON data.py:203-220）：写入 Verification 时 `nt_amount` 由客户端传，服务端不校验。

**改造**：`data.py` 写入分支加：
```python
expected = LABOR_PRICING.get(req.type)
if expected is None: raise HTTPException(400, "未知劳动类型")
if abs(req.nt_amount - expected) > 1:  # 容差 1NT（防小数/汇率）
    raise HTTPException(400, f"定价不符：应为 {expected}NT")
```

### 3.3 封堵 earn-sync 后门

**现状**（W6-RECON nt.py:1094-1133）：`/api/nt/earn-sync` 用户可直接 POST 离线 earn 扣社区池，**不经校核**。

**改造**（涉钱，二选一，列皇帝拍）：
- **A 方案（严）**：加 `Depends(require_admin)` + 必须带 `verification_id` 关联
- **B 方案（保留）**：仅加 `Depends(require_admin)`，不做关联——admin 后台补单专用

> 涉钱，**你定**。

| 测什么 | 点哪 | 该看到 |

| earn-sync 旁路 | 普通用户 POST /api/nt/earn-sync | 403（admin 才能调） |

**太傅注三行**：
- 改造点 3.1 + 3.2 + 3.3 是**涉钱铁基**——不做只发前端，定价分歧、客户端篡价、earn-sync 造币三坑仍在；本稿的"对齐底座"主要治的是形，治本还得治这三件。
- 田间 + 大扫除 套同一套 A 范式（"选对象→选动作→提交→校核→结算"），是底座 v0 "复用 > 创造" 的首次完整示范——animal_care / 厨房录入 后续直接套，不再每页设计。
- 工作台快捷抽屉（H 范式）首次落地——这是"少点几步"总则的具体化，从本稿起，高频操作都该有抽屉入口。
