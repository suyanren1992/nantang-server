## 一、它是什么

**南塘云村是一套让社区劳动被发现、被认可、被激励的数字孪生系统。**

像一个放大镜——打扫、整理、浇水、做饭、修东西、维护社区、办活动，这些事本来每天都在发生。没有系统的时候，它们发生之后就消失了。南塘云村把它们捕捉下来，放大出来，让更多人看到。

但它不止于记录。它是一个**训练场**——在安全的、有反馈的环境里反复尝试，从找到想法、到打磨方案、到推动提案、到落地行动、到评估结果。链条跑通一次，人就成长一步。跑通十次，就不再需要系统引导。

**终极目标：系统退场，习惯留下。** 当社区成员习惯了主动观察、主动劳动、主动认可——当「看见美好」不再需要系统来提醒——南塘云村就完成了任务。留下来的是人：一群会看见、会认可、会创造的人。

> 一个游戏，最好的设计不是让人永远留在里面。而是走出去的时候，发现自己已经变成了更好的人。

## 二、三足鼎立：平台的骨架

南塘云村用三条腿撑起来。任务大厅是枢纽，游戏化的 NT 系统是血液，流过三条腿。

```
                         ┌─────────────────────────┐
                         │     🌐 南塘云村          │
                         │                          │
    社区副本（活动容器）   │  ┌──────────────────┐   │   实景地图（数字孪生）
    ────────────────      │  │   任务大厅（枢纽） │   │   ────────────────
    共创营 · 饭局 · 议事   │  │   NT 经济 · 卡片室 │   │   空间镜像 · 标记
    成员名册 · 活动时间线   │  │   所有任务的入口    │   │   人来人往 · 本地历史
           │              │  └────────┬─────────┘   │         │
           │              │           │             │         │
           └──────────────┴───────────┴─────────────┘         │
                         │                          │
                    🏕️ 在地伙伴   ⚔️ 冒险者   ☁️ 云上访客
```

### 第一条腿：社区副本——活动的容器

管的是南塘本地真实发生的**活动**——共创营、饭局、大扫除、议事。这些活动在平台上被管理、被看见。

- 创建营地/活动 → 成员名册 → 活动时间线 → 营地专属内容流 → 议事讨论空间
- 营队里的任务打上 `camp_id` 标签，进入任务大厅
- 核心情绪：**「我们营队在做什么，外面人好奇」**

### 第二条腿：任务大厅——NT 经济的引擎

**所有任务的统一入口**。不管是实景游戏任务、营地任务、日常任务，都从这里出。

- 任务发布 → 认领 → 提交 → 审核 → NT 结算——全闭环
- 身份筛选：营地任务仅营地成员可见。非成员看到提示卡片（「🃏 共创营正在进行中 · 3 个任务」），制造好奇心
- NT 可抵扣住宿费——**这是经济闭环的关键锚点：真实的劳动换真实的住宿**
- 卡片室（猜+确认双 tab）是任务大厅的社交层：匿名线索→猜谁做的→猜对双方得 NT
- 核心情绪：**「你做了这件事，这是你挣的 NT，可以抵住宿费」**

### 第三条腿：实景地图——数字孪生

三层递进，一层比一层深：

| 层 | 内容 | 一句话 |
|---|---|---|
| 空间数据镜像 | 每间房的状态（干净/脏污度）、每件物品的位置和保质期、每块菜地的作物阶段 | 「这个空间现在什么状态」 |
| 社交存在 | 人来人往——谁住在合作社、谁来了、谁离开了、一起约饭局 | 「谁在这里，可以一起做什么」 |
| 时间沉积 | 这片土地上 26 年发生过的事——变成可收集的任务，找到真人 NPC 去发现 | 「这里曾经发生过什么」 |

实景地图不只是一个被动镜像——它**主动把人推向现实**。平台发任务让你了解南塘的历史，你到现实中找到那个人，完成对话，获得奖励。数字世界给你任务，现实世界给你答案。

- 核心情绪（短期）：**探索欲**——「地图上那个暗着的标记背后是什么」
- 核心情绪（长期）：**被看见**——「我的劳动、我的存在，在这张地图上留下了痕迹」

### 三条腿共享的底色

不是三条腿各分配一种情绪。**快乐、收获、成就感**——这三样是三条腿共享的。

设计哲学只有一句话：**即时反馈 → 正循环 → 习惯内化 → 系统退场。**
游戏乐趣不在于「别人给我任务」，而在于「我自己想做这件事」——由内心的正循环产生动力和行动力，点亮自己的生命。

## 三、它从哪里来

南塘云村不是某一天画在白板上的。它是在南塘——安徽阜阳颍州区三合镇三星村——长了 26 年的东西。

### 这片土地的经历

- **1998 年**，杨云标（标哥）大学毕业回乡，帮村民写举报材料。农民维权协会成立。从维权开始
- **2004 年**，在温铁军倡议下，维权转向乡建。南塘兴农合作社成立——「从哭着维权到笑着乡建」
- **2008 年**，《罗伯特议事规则》在南塘落地。582 页的规则被精简为「南塘十三条」，村民叫它「萝卜白菜规则」。这是中国乡村第一次用议事规则让每个人平等对话——「规则如何让人平等对话」的基因，从这一年开始
- **2022 年**，合作社资金互助爆雷，陷入债务危机
- **2024 年**，南塘 DAO 成立——中国第一个把 Web3 和乡村建设融合的去中心化组织。南塘豆（NT）系统上线——这是 NT 经济的原型
- **2024 年冬**，南塘不知 DAO 成立。一群在地年轻人提出：「去中心化只是方式而非目的」「让乡建更好地乡建」——这是平台设计哲学的直接来源

### 这些经历教了什么

议事规则教了「规则如何让人平等对话」。DAO 的实践教了「技术不能替代日常体验——区块链如果不能融入打扫、做饭、种地，就只是一串代码」。共创营教了「即时反馈能激发最大的参与感——营员离开时最常说的话是：在这里被看见的感觉，外面给不了」。

这些汇成一句话：**用数字孪生映射现实，用即时反馈激励参与，用游戏化让劳动被看见。**

### 谁在做

**在地年轻人是最先的 NPC。** 住在合作社的年轻人——他们不是系统的「用户」，他们是第一批「可被发现的人」。平台发任务让人去找到他们、了解他们在这里做什么、为什么来这里。

村民和合作社的老人（标哥、在地伙伴）——他们的故事、他们经历过的 26 年——是更深层的本地历史。这些不是远期愿景，是正在被沉淀的内容。只是现在还停留在口头上、记忆里，没有形成可展示、可收集的系统。

## 四、面向谁

| 角色 | 定义 | 核心诉求 |
|---|---|---|
| **在地成员** | 实际住在社区、有住宿记录的用户 | 记录劳动、获得认可、参与社区治理 |
| **云村民** | 未入住但关注社区的线上用户 | 关注社区动态、有限参与 |
| **管理员** | 社区运营者 | 发社区任务、审核新人、管理资金池 |
| **共建者** | 积极参与建设的成员 | 发社区任务、审核新人任务 |
| **真人 NPC** | 在地生活的年轻人、合作社成员、村民——他们的故事可被发现 | 被认识、被询问、成为社区历史的活入口 |

## 五、核心功能与 MVP 边界

### MVP 做什么

| 模块 | 功能 | 所属腿 |
|---|---|---|
| 任务系统 | 创建任务（escrow NT）→ 认领 → 提交 → 审核 → 结算 NT | 任务大厅 |
| NT 经济 | NT 余额、冻结 NT、账本、社区池、贡献值、经验值、信任分 | 任务大厅 |
| NT 抵住宿费 | 劳动换 NT → NT 抵扣住宿——经济闭环的关键锚点 | 任务大厅 |
| 卡片室 | 匿名行为卡片「猜谁做的」→ 猜对得 NT；自主贡献上报 → 验证得 NT | 任务大厅 |
| 营地 | 创建营地、成员管理、营地任务（仅成员可见） | 社区副本 |
| 村口+工作台 | 暗色毛玻璃登录页 → 亮色工作台（底部五 Tab） | 全局 UI |
| 实景地图·数据层 | 空间状态、标记系统、物品追踪、住宿管理 | 实景地图 |
| 在地 NPC（内容） | 在地年轻人作为「可被发现的人」——手工创建任务，不建系统 | 实景地图 |
| 档案室 | 本地历史查阅——游戏化入口，现有内容先沉淀 | 实景地图 |
| 公约版本化 | 公约展示、修改提案、版本化闭环 | 社区副本 |

### MVP 不做什么

| 不做的事 | 原因 | 何时做 |
|---|---|---|
| 社区副本的完整议事系统（提案→讨论→投票） | 当前营地规模小，公约版本化已覆盖基本议事需求 | 30 人+ |
| 实景地图的硬件感知层（摄像头/手环/GPS 融合） | 成本+隐私复杂度高；先用人工上报+标记系统覆盖 | 硬件采购到位后 |
| 真人 NPC 系统化（NPC 管理后台/任务模板） | 先手工做内容，验证「找到真人 NPC」这个模式是否跑得通 | 内容验证成功后 |
| 本地历史的完整时间滑条 | 内容沉淀需要时间；先让档案室有东西可查 | 档案室积累 20+ 条目后 |
| 周期性任务自动生成（服务端 cron） | 外层设计项目 C，依赖 Phase E 入住系统 | 在地成员体系就位后 |
| 赏金任务随机掉落 | 远期游戏化层 | 周期任务稳定后 |
| 原生 App（iOS/Android） | 移动端 Web 已覆盖核心场景 | 用户强烈需求时 |
| 实时聊天/IM | 社区规模小，现有团队动态+线下沟通足够 | 30 人+ |
| 公开注册（无邀请码） | 邀请码制保护社区安全 | 暂不计划 |

## 十一、验收规则

第一版「完成」的判据：

1. 一条委托链路跑通：新人注册→登录→认领任务→提交→被审核→NT 到账
2. 一条校核链路跑通：上报劳动→另一个人验证→NT 从社区池发出
3. 一张匿名卡片闭环：被猜中→猜对者 NT 到账→被猜者确认
4. **NT 抵住宿费跑通**：用户 NT 余额可抵扣住宿费用——经济闭环的关键锚点验证
5. 营地任务身份筛选生效：非成员看到好奇卡片，成员看到完整任务
6. 所有接口有权限校验（越权请求被拦截，有日志证据）
7. 数据库有备份且恢复流程已验证
