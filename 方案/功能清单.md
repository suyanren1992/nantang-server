## P0 · MVP 必须（9 项）

### F1. 登录注册与角色系统
- **用户故事**：作为一个新来南塘的人，我输入用户名和密码就能注册/登录，系统知道我是谁、什么角色
- **验收判据**：注册成功→token 返回→登录可用 token 访问接口；邀请码校验；角色（admin/builder/adventurer/npc/visitor）正确分配
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`auth.js`（428 行）完整实现注册/登录/鉴权/角色变更。`server/routes/auth.py`（189 行）服务端鉴权。D-3 用户名枚举修复已上线。
- **证据**：`auth.js:1-428` / `routes/auth.py:1-189` / BUG_TRACKER D-3 ✅

### F2. 任务系统（创建→认领→提交→审核→结算）
- **用户故事**：作为在地成员，我可以发布委托任务（冻结 NT）、认领别人的任务、提交完成证据、审核别人的提交——整条链路走完，NT 正确流转
- **验收判据**：发布→escrow NT 扣除；认领→状态变更；提交→待审核；审核通过→NT 到账+账本记录；取消未认领→NT 退回
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`nt.py`（1053 行）任务 CRUD 完整实现。`nt-core.js`（768 行）客户端 NT 引擎。D-7 任务状态 400 修复已上线。
- **证据**：`nt.py:518-650` / `nt-core.js:217` submitTask / BUG_TRACKER D-7 ✅

### F3. NT 经济系统（余额/账本/社区池/贡献值/经验值）
- **用户故事**：我的每一次劳动都被记成 NT、贡献值和经验值。NT 可以花（抵住宿费/发委托），贡献值决定权限，经验值解锁称号。社区池有预算约束，不是无限印钱。
- **验收判据**：NT 余额实时准确；账本每笔流水可查；社区池余额=初始+流入-流出；贡献值/经验值只涨不跌（经验值）/交易磨损 75%归卖家+25%入社区池（贡献值）
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`nt.py` NT 记账/提现完整。`models.py` NTLedger/CommunityPool 模型。D-5 资金行锁修复已上线。D-18 资金契约全量接服务端已上线。
- **证据**：`models.py:40-54` NTLedger / `nt.py:1-1053` / BUG_TRACKER D-5/D-18 ✅

### F4. NT 抵住宿费（经济闭环关键锚点）
- **用户故事**：我挣的 NT 可以用来付住宿费——这是「真实劳动换真实住宿」的证明。不是游戏积分，是真的能省钱的。
- **验收判据**：住宿费按日自动计算→从 NT 余额抵扣→不足时欠费记录→退房时结算欠费。退房后角色降级为 visitor，location 清空。
- **归属腿**：任务大厅（经济闭环）
- **现状**：⚠️ 服务端已实现退房结算逻辑，但**自动日扣住宿费**未完全确认上线。`accommodation.py:78-105` checkout 含欠费结算。`nt.py:62-73` `_get_accommodation_status`。`nt.py:163` 注释标记「ponytail: C2/C2.5 就位后补 accommodation」。
- **证据**：`accommodation.py:78-105` / `nt.py:62-73` / `nt.py:163` 注释

### F5. 卡片室（匿名发现+自主上报）

- **归属腿**：任务大厅（社交层）

- **优先级理由**：成本+隐私复杂度高。当前人工上报+标记系统可覆盖 MVP。
- **归属腿**：实景地图

### F20. 周期性任务自动生成
- **用户故事**：每天自动生成大扫除/日常清理/堆肥翻拌任务——不用等人手动发。仅在地成员可见。

## 🎭 身份进阶线专节

### 角色状态机

```
游客（无账号）
  │ 注册
  ▼
🏕️ 云村民（visitor）        ← isMember: false · 在线看内容+发任务 · 领不了在地任务
  │ 使用冒险者邀请码
  ▼
⚔️ 冒险者（adventurer）     ← isMember: true · 可加入营队 · 可领营队任务 · 可见卡片室
  │ 被管理员设为共建者
  ▼
🧱 共建者（builder）        ← isMember: true · 可管理营地 · 见成员 · 结算任务
  │ 系统首个用户 / 手动
  ▼
🧙 管理员（admin）          ← isMember: true · 全部权限 · 创世终端 · 邀请码管理
```

**旁支**：👥 在地伙伴（npc）← isMember: true · 等同于冒险者权限 · 代表在地居民角色

### 角色与代码字段全量对照

| 角色 | 代码常量 | ROLE_TITLES (`nt.js:18`) | ROLE_CAPABILITIES (`nt.js:22-33`) |
|---|---|---|---|
| 🧙 管理员 | `admin` | `🧙管理员` | `isMember:true, canClaimCamp:true` · 13 tabs |
| 🧱 共建者 | `builder` | `🧱共建者` | `isMember:true, canClaimCamp:true` · 11 tabs |
| ⚔️ 冒险者 | `adventurer` | `⚔️冒险者` | `isMember:true, canClaimCamp:true` · 4 tabs |
| 👥 在地伙伴 | `npc` | `👥在地伙伴` | `isMember:true, canClaimCamp:true` · 4 tabs |
| 🏕️ 云村民 | `visitor` | `🏕️云村民` | `isMember:false, canClaimCamp:false` · 3 tabs |

**用户数据字段**（`getUsers()` → `auth.js:10`）：
- `name`：用户名
- `role`：`admin` | `builder` | `adventurer` | `npc` | `visitor`
- `avatar_seed`：DiceBear 头像种子
- `password`：加密后密码
- `world_id`：冒险者绑定邀请码
- `season_history`：历期身份变更记录 `[{role, period, changed_at}]`
- `uid`：全局唯一 ID
- `created`：注册日期
- `season`：当前期数

**身份工牌**（`getIdentity()` → `auth.js:50-181`）：
- 固定层：`uid`, `name`, `created`
- 变化层：`role`, `title`, `season`, `worldId`
- 履历：`badges[]`, `history[]`
- 权限：`can: {isMember, postTask, claimTask, reviewTask, manageNT, seeMembers, seeNTAdmin, inviteCode}`
- 界面：`ui: {tabs, defaultPage, mode, showGenesisBtn, showBuilderBar, showQuestBoard, workspaceSections}`
- 资料：`profile: {avatar, gender, bio, phone, address, wallet, skills, customTitle}`
- 数据：`stats: {nt, ntCamp, ntPersonal, daysActive, tasksActive, tasksSubmit, tasksDone, achievements}`

**权限核心判断**（`auth.js:38-43`）：
- `userCan(user, cap)` → 读取 `ROLE_CAPABILITIES[user.role][cap]`
- `isMemberByRole(role)` → `ROLE_CAPABILITIES[role].isMember`
- `isMemberByName(name)` → 查用户 role 再判 isMember
- `canUserClaim(user, task)` → 完整 8 步校验（角色/状态/名额/已领/可见性）→ `auth.js:203-239`
