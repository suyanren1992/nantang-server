## P0 · MVP 必须（7 项）

### F1. 登录注册与角色系统
- **用户故事**：作为一个新来南塘的人，我输入用户名和密码就能注册/登录，系统知道我是谁、什么角色
- **验收判据**：注册成功→token 返回→登录可用 token 访问接口；邀请码校验；角色（admin/builder/adventurer/visitor）正确分配
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`server/routes/auth.py`（189 行）完整实现注册/登录/鉴权。`nantang-mobile/js/auth.js`（428 行）前端登录注册 UI。D-3 用户名枚举修复已上线。
- **证据**：`auth.js:1-428` / `routes/auth.py:1-189` / BUG_TRACKER D-3 ✅

### F2. 任务系统（创建→认领→提交→审核→结算）
- **用户故事**：作为在地成员，我可以发布委托任务（冻结 NT）、认领别人的任务、提交完成证据、审核别人的提交——整条链路走完，NT 正确流转
- **验收判据**：发布→escrow NT 扣除；认领→状态变更；提交→待审核；审核通过→NT 到账+账本记录；取消未认领→NT 退回
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`server/routes/nt.py`（1053 行）任务 CRUD 完整实现。`nantang-mobile/js/nt-core.js`（768 行）客户端 NT 引擎。D-7 任务状态 400 修复已上线。
- **证据**：`nt.py:518-650` / `nt-core.js:217` submitTask / BUG_TRACKER D-7 ✅

### F3. NT 经济系统（余额/账本/社区池/贡献值/经验值）
- **用户故事**：我的每一次劳动都被记成 NT、贡献值和经验值。NT 可以花（抵住宿费/发委托），贡献值决定权限，经验值解锁称号。社区池有预算约束，不是无限印钱。
- **验收判据**：NT 余额实时准确；账本每笔流水可查；社区池余额=初始+流入-流出；贡献值/经验值只涨不跌（经验值）/交易磨损 75%归卖家+25%入社区池（贡献值）
- **归属腿**：任务大厅
- **现状**：✅ 已上线。`server/routes/nt.py` NT 记账/提现完整。`server/models.py` NTLedger/CommunityPool 模型。D-5 资金行锁修复已上线。D-18 资金契约全量接服务端已上线。
- **证据**：`models.py:40-54` NTLedger / `nt.py:1-1053` / BUG_TRACKER D-5/D-18 ✅

### F4. NT 抵住宿费（经济闭环关键锚点）
- **用户故事**：我挣的 NT 可以用来付住宿费——这是「真实劳动换真实住宿」的证明。不是游戏积分，是真的能省钱的。
- **验收判据**：住宿费按日自动计算→从 NT 余额抵扣→不足时欠费记录→退房时结算欠费。退房后角色降级为 visitor，location 清空。
- **归属腿**：任务大厅（经济闭环）
- **现状**：⚠️ 服务端已实现退房结算逻辑，但**自动日扣住宿费**未完全确认上线。`server/routes/accommodation.py:78-105` checkout 含欠费结算。`nt.py:62-73` `_get_accommodation_status` 查询住宿状态。`nt.py:163` 注释标记「ponytail: C2/C2.5 就位后补 accommodation」。
- **证据**：`accommodation.py:78-105` / `nt.py:62-73` / `nt.py:163` 注释

### F5. 卡片室（匿名发现+自主上报）
- **用户故事**：我做了好事（打扫/翻堆肥/收番茄），系统记下匿名线索。社区里的人看到线索猜「谁做的」——猜对了双方都得 NT。如果没人猜，我可以自己上报（附前后对比照），等人验证。
- **验收判据**：猜 tab：匿名卡片展示→选人猜测→猜对双方 NT 到账→猜错本轮出局。确认 tab：上报劳动→写 verification 队列→他人确认/驳回→NT 从社区池发出。双 tab 可切换。防作弊 4 条规则生效（非自校核/1h 冷却/日限 10 次/3 次驳回永久拒绝）。
- **归属腿**：任务大厅（社交层）
- **现状**：✅ 已上线。`ui-cardroom.js`（1368 行）完整实现双 tab。E-1 已确认 index.html:529 加载此模块（**纠正旧架构文档错误**）。校核制纯客户端运行——服务端化待外层设计项目 A。
- **证据**：`ui-cardroom.js:357` openCardRoom / `ui-cardroom.js:572` renderCardRoom 双 tab / BUG_TRACKER E-1 实证

### F6. 村口+工作台 UI
- **用户故事**：打开 App，先看到暗色毛玻璃的村口（三张滑动卡片+底部玩家卡）→点击进入亮色工作台（底部五 Tab：地图/任务大厅/卡片室/消息/我的）。两个模式的视觉切换自然流畅。
- **验收判据**：村口暗色主题——毛玻璃卡片滑动/漂浮粒子动画/玩家卡片悬浮。工作台亮色主题——五 Tab 可切换/sticky bottom tab bar/安全区适配。双模式视觉语言符合 DESIGN.md 规范。
- **归属腿**：全局 UI
- **现状**：✅ 已上线。`index.html`（1365 行）完整登录/村口/工作台 HTML。D-9 UI 批次修复（小屏裁剪/safe-area/原生弹窗/搜索防抖/滚动锁定）已上线。DESIGN.md 设计 Token 已文档化但未接入代码。
- **证据**：`index.html:1-1365` / DESIGN.md 完整设计 Token / BUG_TRACKER D-9 ✅

### F7. 实景地图·数据层（空间状态/标记/物品/住宿管理）
- **用户故事**：打开地图，看到每间房的状态（干净/脏污/谁在）、每件物品的位置和保质期、每块菜地的作物阶段。住宿信息一目了然。
- **验收判据**：空间状态灯（🟢干净/🟡需打扫/🔴紧急）。标记系统：创建→系统校验→核验→确认。物品追踪：放入/取出/过期提醒。住宿：入住/退房/房间状态/欠费。
- **归属腿**：实景地图
- **现状**：✅ 数据层已上线。但产品说明书 v11 的硬件感知层（摄像头/手环/GPS）属远期，当前依赖人工上报+标记。住宿管理 `routes/accommodation.py`（166 行）完整。
- **证据**：`accommodation.py:1-166` / `data.py:513` 地图数据同步 / BUG_TRACKER 住宿相关条目

## P1 · MVP 应有（5 项）

### F8. 营地系统（创建/成员/营地任务筛选）
- **用户故事**：我创建一个营地（或加入别人的），营地里能看到专属的任务和活动时间线。营地任务在任务大厅只对成员可见——外面的人看到「🃏 共创营正在进行中 · 3 个任务」的好奇卡片。
- **验收判据**：创建营地→邀请成员→营地任务仅成员可见→营地活动时间线→营地结算（创建者/admin 可结算）。非成员在任务大厅看到营地好奇卡片而非具体任务。
- **归属腿**：社区副本
- **现状**：✅ 营地创建/成员/UI 已上线。**营地任务身份筛选未完全确认**——当前代码 `ui-camp.js` 用 `scope === 'camp'` 过滤财务数据，但任务大厅对营地任务的身份筛选逻辑需核实。D-10 营地结算越权修复已上线。
- **证据**：`ui-camp.js:1587` / `routes/camps.py:221` / BUG_TRACKER D-10 ✅

### F9. 在地 NPC（内容先行）
- **用户故事**：合作社里住着的年轻人——每个人都是一条可发现的故事线。平台发任务让我去找到他们、了解他们为什么来这里、在这里做什么。
- **验收判据**：手工创建 NPC 发现任务→用户接任务→找到真人→完成任务→获得 NT。**不建系统，先做内容**——验证「找到真人 NPC」模式是否跑通。
- **归属腿**：实景地图
- **现状**：🟡 系统就绪（任务系统+卡片室可用），**内容空缺**——尚未创建 NPC 相关任务。档案室 `ui-archive.js`（422 行）已实现社区记录查阅入口，可作为本地历史沉淀的起点。
- **证据**：`ui-archive.js:208-230` 档案室房间注入大地书房 / 无 NPC 任务内容

### F10. 档案室（本地历史查阅）
- **用户故事**：我想了解南塘 26 年的历史——标哥怎么从维权走到乡建、萝卜白菜规则怎么来的、DAO 实验发生了什么。档案室里有这些故事，通过游戏化的方式查阅。
- **验收判据**：档案室入口可访问→社区记录/成员目录/运行日志可查阅→通过游戏化方式（任务线索）引导查阅。
- **归属腿**：实景地图
- **现状**：✅ 档案室 UI 已接入大地书房（`ui-archive.js:208-230`）。**内容空缺**——本地历史条目尚未沉淀到可查阅的程度。
- **证据**：`ui-archive.js:208-230` / 立项文档 §三 南塘历史

### F11. 社区公约版本化
- **用户故事**：社区规则不是管理员一个人定的——任何人可以提修改提案，两人校核通过后自动生效。每次修改都有历史记录，可追溯。
- **验收判据**：管理员发起提案→待校核列表展示→两人确认→自动 apply→configHistory 记录。提案者不能自校。服务端权威存储（换设备不丢失）。
- **归属腿**：社区副本
- **现状**：✅ D-15 已上线。完整闭环：提案入口+待校核展示+服务端 sync_shared 同步。
- **证据**：`app-data.js:539-561` proposeConfigChange/verifyConfigChange / `data.py:416-500` 公约同步 / BUG_TRACKER D-15 ✅

### F12. 安全防线（D 系列全 18 卡）
- **用户故事**：我用这个平台时，不用担心别人看到我的数据、改我的余额、冒用我的身份。平台的安全不是「看起来安全」，而是每道防线都有证据。
- **验收判据**：CORS 精确白名单/邀请码校验/用户名注入拦截/资金行锁/越权校验/输入过滤/XSS防护/HTTPS全站/密钥不入代码。D-19/D-20 回归测试覆盖关键漏洞。
- **归属腿**：任务大厅（横切）
- **现状**：✅ D 系列 16 张安全卡全部已上线。D-19（22 条回归测试）+ D-22（部署总检）就位。D-23（月度安全扫描）就位。
- **证据**：BUG_TRACKER D-2~D-18 全线 ✅ / D-19 22/22 ✅ / D-22 3/3 ✅

## P2 · 远期（5 项）

### F13. 社区副本完整议事系统
- **用户故事**：社区里的大事小事，不用等开会——提案→讨论→投票→执行，全在平台上走。议事规则继承南塘「萝卜白菜规则」的基因。
- **优先级理由**：当前营地规模小，公约版本化已覆盖基本议事。30 人+再建完整系统。
- **归属腿**：社区副本
- **现状**：🔴 未开始。公约版本化（F11）是议事系统的最小可行单元。

### F14. 实景地图硬件感知层
- **用户故事**：我不用手动上报——摄像头捕捉到我在画室打扫，手环感知到我在菜地劳作。系统默默记录线索，等有人来发现。
- **优先级理由**：成本+隐私复杂度高。当前人工上报+标记系统可覆盖 MVP。
- **归属腿**：实景地图
- **现状**：🔴 产品说明书 v11 L1/L2 已设计（Frigate NVR+ESP32-CAM+手环），未采购未部署。

### F15. 周期性任务自动生成
- **用户故事**：每天自动生成大扫除/日常清理/堆肥翻拌任务——不用等人手动发。仅在地成员可见。
- **优先级理由**：依赖 Phase E 入住系统（在地成员定义）+ 服务端 cron 就位。
- **归属腿**：任务大厅
- **现状**：🔴 外层设计项目 C 已设计（`server/config/periodic_tasks.json` 模板定义），未施工。

### F16. 赏金任务随机掉落
- **用户故事**：偶尔弹出一个小任务——打苍蝇/喂猫/浇水——做完有 NT。像游戏里的随机事件，让日常有点惊喜。
- **优先级理由**：远期游戏化层——周期任务稳定后再做。
- **归属腿**：任务大厅
- **现状**：🔴 外层设计项目 C 已设计，标记为远期。

### F17. 实时聊天/IM
- **用户故事**：在平台里直接和社区成员聊天，不用跳出去用微信。
- **优先级理由**：社区规模小（20 人），现有团队动态+线下沟通够用。
- **归属腿**：实景地图
- **现状**：🔴 未开始。
