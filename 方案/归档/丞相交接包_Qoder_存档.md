## 四、丞相操作规程（5 步，每步有验证命令）

1. **制卡前必亲证**：grep/读真仓现行代码，勘察保质期 24h，不亲证不制卡。
2. **派工**：卡面落 `方案/任务卡/编号_名称.md`，贴文给对应营。码卡须御笔；纯文档/纯测试小卡丞相可代行。
3. **副署（验收）**：回执到 → 必跑：
   ```bash
   cd 真仓 && git log --oneline -3 && git show <hash> --stat
   cd 真仓/server && JWT_SECRET=test_secret_for_pytest "C:\Python314\python.exe" -m pytest tests/ -q
   cd 真仓/nantang-mobile && node --check js/<改动文件>
   cd 真仓/nantang-mobile/tests && npm test
   cd 真仓/server && JWT_SECRET=test_secret_for_pytest "C:\Python314\python.exe" scripts/deploy_check.py --skip-smoke
   ```
   diff 亲读与回执主张逐条对；**前后端契约字段名逐字对**。不符即打回写明理由。
4. **出闸**：push 是御笔。砚仁说「出闸」后：
   ```bash
   git log origin/main..HEAD --oneline   # 逐项对账，笔笔已副署才推
   git push origin main
   ```
   推后提醒砚仁：**5-8 分钟 Render 部署窗口内别复测**。
5. **记账**：先写总账后回话；砚仁报一症登一编号；**复核坏项当场转卡，不许悬空**。

## 六、先议后卡 + 意见审查（2026-07-27 砚仁准）

1. 砚仁提需求 → 丞相先出**议单**：病灶理解 + 立案分诊 + 为什么这么修 + 分几步 + 先后顺序。
2. 逐组讨论，砚仁拍板后丞相才开任务卡。**禁止「需求→直接发卡」。**

## 七、立案分诊四分法（2026-07-27 砚仁准）

任何 bug 立案勘察，第一步先分诊：

| 病型 | 识别特征 | 验证路径 |
|---|---|---|
| 代码病 | 逻辑错、字段名错、空指针 | grep + 实跑端点 |
| 环境病 | 本地好上线崩、连不上库 | 环境变量/连接串/依赖版本 |
| 前后端病 | 接缝错位、字段对不上 | 契约对照 + `?v=` 审计 |
| 并发时序病 | 偶发、双花、串号 | 真 PG 行锁测试，判据从严 |
