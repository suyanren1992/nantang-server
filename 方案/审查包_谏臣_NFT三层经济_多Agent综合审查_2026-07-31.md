# NFT 三层经济设计稿 v1 · 多 Agent 综合审查

> **审查范围**：NFT-三层经济设计稿_v1.md 全文（§一~§九）
> **对照基线**：NT经济规则设计稿 v3.1 + NT闭环体检 v0.3.2 + A-LABOR-BE/FE 任务卡 + chain_scanner.py 真仓
> **方法**：6 个专业 Agent 独立审查 → 交叉去重 → 按主题归类 → 统一严重性定级

---

## 执行摘要

NFT 三层经济设计稿的**核心思路正确**——将「钱」和「功劳」拆开，NT 守恒不印，劳动价值溢出到 NFT 层。三层结构（NT→NFT→勋章）的单向阀设计在概念上是健康的。

但 6 个 Agent 独立审查后，在以下维度发现了**一致的、跨视角收敛的结构性问题**：

| 维度 | Critical/P0 数 | 核心矛盾 |
|------|:---:|---|
| 经济安全 | 5 | self-mint 击穿单向阀、badge_credit 无经济需求、零 NT 刷劳动 |
| 系统集成 | 3 | 治理权重违宪、pool_refill 删除时序、端点命名冲突 |
| 技术可行 | 3 | 钱包矛盾、成本差 100x、冷钱包实为热钱包 |
| 用户体验 | 4 | 7 种价值体系过载、self-mint 0% 可用、"NFT" 洋名无意义 |
| 长期运营 | 3 | 勋章 treadmill 停滞、credit 通胀、里程碑沙漠 |

**总判**：设计方向对，但**不可立即派卡**。需先解决 6 个 P0 阻断项，修正 8 个 P1 结构问题，P2 可在施工中边做边改。

## 一、P0 阻断项（不改则上线即崩 · 6 项）

### P0-1：self-mint 无限复制——badge_credit 可被无限印

**发现 Agent**：Security #1 · Economy P0-2 · Systems #P1-3（三角交叉验证）

**攻击路径**：
1. 用户获得 platform NFT A（labor_count=50, badge_credit=50）
2. 调用 self-mint → 获得 self NFT B（可转让，badge_credit=50）
3. 转让 B 给用户 2
4. **再次**调用 self-mint（同一 source A）→ 获得 self NFT C
5. 无限重复。每次复制携带完整 badge_credit

**根因**：数据模型无 `has_self_minted` 标记，无唯一性约束，无 `source_nft_id` 外键。

**修复**（三选一）：
- **方案 A（推荐）**：platform NFT 加 `has_self_minted: Boolean`，self-mint 时行锁置 true，后续拒绝
- **方案 B**：self-mint 时 platform NFT 的 badge_credit 清零（额度转移，不复制）
- **方案 C**：self-minted NFT 的 badge_credit=0（纯收藏品，不可兑换）


### P0-2：badge_credit 竞态条件——双花漏洞

**发现 Agent**：Security #2

**攻击路径**：用户同时从两个浏览器 Tab 发送 redeem 请求 → 两个线程都读到 badge_used=0 → 都验证通过 → 实际消费 2x 额度但只记录 1x。

**根因**：设计稿未要求行级锁。现有 NT 系统已通过 `with_for_update()` 解决同类问题（D-17），NFT 设计遗漏。

**修复**：所有 badge redeem/spend 端点在读 badge_used 前必须 `SELECT ... FOR UPDATE`。


### P0-3：劳动 NFT「治理权重」直接违宪

**发现 Agent**：Systems #9（唯一直接从御批文本对照的发现）

**冲突**：
- NFT 设计 L43：「用途：履历 / **治理权重** / 兑换 FT 勋章」
- v0.3.2 御批 §十：「CV/XP/等级/勋章**全不挂治理权**」
- A-LABOR-FE 已验收代码：`honorary: true`

**修复**：全量替换「治理权重」为「荣誉凭证 / 劳动履历 / 社区声望」。若坚持 NFT 应挂治理权，须先提请砚仁修改 v0.3.2 御批。


### P0-4：删除 pool_refill 的时序——NFT 系统未上线前出现无兜底窗口

**发现 Agent**：Economy P0-1 · Systems #1（双视角验证）

**风险链**：
1. Phase 0 立即删 pool_refill（NT-P0-6 卡已派）
2. 运营池水位 151-299 区间失去自动恢复（自动调水仅在 <150 触发）
3. 池落至此区间 → 用户被 P0-1 拒绝 → 无自动恢复 → 等 admin 手动注资
4. NFT Phase 1 尚未排期（可能 2 周+）

**修复**：
- 将自动调水触发阈值从 `<150` 提升到 `<300`
- 且治理议单 NT-代币-治理-v0 尚待砚仁就 pool_refill 批甲/乙/丙——Phase 0 应等御批后再执行


### P0-5：self-mint 需要用户有钱包——但目标用户没有

**发现 Agent**：Tech Dir #1 · UX #1 · Security #14（三角交叉验证）

**矛盾**：
- 现有系统已**正式否决**链上 P2P，理由：「60 后村民无加密钱包，A 卡死在钱包操作步」
- self-mint 要求：浏览器钱包插件 + OP Chain 配置 + ETH 余额 + gas 签名
- 复杂度是 P2P 转账的 10 倍

**结论**：self-mint 对当前用户群 **100% 不可用**。这是存在性问题，不是 UX 问题。

**修复**（三选一）：
- **方案 A（推荐）**：平台托管钱包——用户点按钮，平台后端签名。gas 从 NT 余额扣
- **方案 B**：砍掉 self-mint，Phase 1-3 只做 platform NFT
- **方案 C**：接受现状——self-mint 仅为钱包用户可用（标注「高级功能」）


### P0-6：FT 勋章无独立于 NT 的需求拉动——经济激励倒挂

**发现 Agent**：Economy P0-3 · Live Ops #1（双视角验证）

**问题**：勋章能买的东西（food/stay/event）NT 都能买，且勋章获取成本更高（劳动→NFT credit→勋章 vs 劳动→NT）。理性用户绝不用勋章。

**后果**：Layer 2→Layer 3 兑换链路断裂。badge_credit 无限堆积，无人消费。

**修复**：
- 勋章必须解锁 NT 买不到的东西：专属限量商品、活动优先权、特殊称号展示
- 或勋章购买同商品有折扣（NT 10 → 勋章 7 credit）
- 数据模型加 `badge.nt_exclusive: Boolean` 标记

## 二、P1 结构问题（显著增加风险/困惑 · 8 项）

### P1-1：CV / XP / labor_count 三套劳动追踪高度重叠

**发现 Agent**：Economy P1-1 · Game Designer P0-1

| 体系 | 公式 | 增减 | 用途 |
|------|------|------|------|
| CV | floor(nt/2) | 劳动+ | 社区权限 |
| XP | 分类+周衰减 | 只涨 | 称号解锁 |
| labor_count | 1次=1 | 只涨 | NFT铸造+勋章兑换 |

**问题**：同一劳动事件需写三个字段，维护成本×3，出错概率×3。labor_count 的 1=1 设计导致轻劳动在勋章获取上比重劳动更优（10 次 take_trash vs 1 次 chef）。

**修复**：badge_credit = floor(nt_amount / N)（建议 N=10），让勋章反映劳动价值而非简单次数。


### P1-2：用户面临 7 种价值体系——认知过载

**发现 Agent**：Game Designer P0-2 · UX #2

现有 5 种（NT / CV / XP / Trust / 称号）+ 新增 2 种（劳动 NFT / 勋章）= 7 种。65 岁村民需要理解 7 套规则。

**修复**：UI 层合并为 3 个表面概念——
- 💰 **钱**（NT + Frozen + Escrow + 住宿应付 → 可用余额 / 待处理）
- 🏅 **等级**（CV + XP + Trust + 称号 → 一个等级条）
- 📜 **劳动记录**（NFT + 勋章 → 劳动相册，非财务仪表盘）


### P1-3：劳动 NFT 与 XP 里程碑重叠——动机稀释

**发现 Agent**：Game Designer P0-1

XP 解锁称号（园丁/厨神），NFT 在 100/500/1000 铸造里程碑，勋章也是成就——**同一行为触发三个系统的奖励**，每个的意义被除以三。

**修复**：统一为一个 progression spine。推荐：XP 做主脊柱，NFT 是 XP 里程碑的**呈现格式**（「你达到 100 XP → 铸一枚 NFT 纪念」），勋章是称号的**视觉表达**。


### P1-4：gas 成本估算差 20-100 倍

**发现 Agent**：Tech Dir #2

提案称 $0.30/月（30 人）。实际：
- OP Chain gas：~$6-8/月（30 次 mint × $0.20/次）
- IPFS Pinata 付费方案：$20/月
- 合约部署：$50-200（一次性）
- **实际：$6-28/月**

**修复**：重算成本，提请砚仁批 gas 预算。metadata-only IPFS 可留在免费层。


### P1-5：平台冷钱包实为热钱包

**发现 Agent**：Tech Dir #3 · Security #4

Cron 自动签名 = 私钥在服务器 = 热钱包。且多签（2-of-2）下，月度批量铸造需两人手动签名——自动化不可能。

**修复**：专用低余额热钱包（月充值 $10 gas），多签冷钱包永不触网。


### P1-6：badge_credit 通胀—— faucet >> sink

**发现 Agent**：Live Ops #5

用户每月赚 20-30 credit，勋章消耗 50-200 credit。但 30 人社群中「好勋章」3-9 个月耗光库存 → credit 堆积 → 无物可兑。

**修复**：季度轮换勋章库存 + 消耗型勋章 + credit 12 月后半衰。


### P1-7：端点命名 /api/nft/ 与 /api/nt/ 一字之差

**发现 Agent**：Systems #11

grep "nt" 同时匹配两类端点。开发者混淆风险高。

**修复**：`/api/nft/` → `/api/labor-nft/`。


### P1-8：「勋章」一词双重含义

**发现 Agent**：Systems #10

- NT 闭环 v0.2：勋章 = CV 达标荣誉（铁锄头/金锄头）
- NFT 设计：FT 勋章 = 消费券

**修复**：FT 勋章 → 「消费券」或「兑换券」。荣誉勋章保留原名。
