## B-5 坚持/签到归零

### 根因

三个并发缺陷导致客户端签到/活动记录丢失：

| 缺陷 | 文件:行号 | 描述 |
|------|-----------|------|
| **A（主因）** | [app-data.js:231](nantang-mobile/js/app-data.js#L231) | `_saveShared` 序列化对象不含 `activity_log` → 刷新即丢 |
| **B（并发主因）** | [core.js:957](nantang-mobile/js/core.js#L957) | `syncAll` 对 `activity_log` 做直接赋值覆盖（`=`），非合并（`concat`/去重） |
| **C（从因）** | [app-data.js:13-47](nantang-mobile/js/app-data.js#L13) | `init()` 未初始化 `activity_log` 默认值 → 启动后为 `undefined` |

### 触发链路

```
登录 → enterVillage() [core.js:1044]
→ API.syncAll() 拉取全量数据
→ _mergeSyncData() 回调 [core.js:957] → data.activity 直接覆盖 activity_log
→ 本地未同步到服务端的条目全部丢弃
→ 若服务端 activity 为空 → 本地归零
```

60 秒轮询不覆盖 `activity_log`（轮询路径安全），但每次登录的 `syncAll` 必定触发覆盖。

### 修法建议

1. **治标**：`_saveShared` 加 `activity_log` 字段 → 刷新不丢
2. **根治**：`_mergeSyncData` 改为智能合并（按 `time+type+text` 去重追加，不覆盖）
3. **防御**：`init()` 加 `activity_log = []` 默认值

### 爆炸半径

- 影响：所有用户的活动动态（签到/任务/角色变更/打赏/发现）。每次登录必触发。
- 严重：🔴 高。用户感知为「坚持归零」「时间线清空」。

## B-4 住宿日期选择界面反复闪

### 根因（四个并发缺陷）

#### A（主因）：`_calNav()` 整个日历 outerHTML 暴力替换

**文件**: [app.js:1731-1735](nantang-mobile/js/app.js#L1731)

```javascript
function _calNav(dir) {
  _calMonth += dir;
  var wrap = document.querySelector('.cal-wrap');
  if (wrap) wrap.outerHTML = _renderMiniCalendar();  // ← 闪的根
}
```

每次翻月：撕掉旧 `.cal-wrap`（含所有日期格子、月份标题、导航按钮）→ 解析新 HTML → 插入。步骤间有 1-2 帧空白期，肉眼可见闪。快速连续翻月时反复闪。

#### B（辅因）：`_showStaySheet()` 全量 Tear down / Rebuild

**文件**: [app.js:1494-1658](nantang-mobile/js/app.js#L1494)

任何触发 `_showStaySheet()` 的操作（点房间、点添加物品等）都会全量 DOM teardown → rebuild。入住卡开着时，这些操作直接摧毁并重建日历。

#### C（架构债）：`renderMgmtPanel('stay')` 与 `_showStaySheet()` 双通道冲突

- [app.js:1403](nantang-mobile/js/app.js#L1403)：`renderMgmtPanel` 对 `stay` 调 `_showStaySheet` → 不返回 HTML → `mgmtBody.innerHTML = ""`
- [app.js:1656](nantang-mobile/js/app.js#L1656)：`_showStaySheet` 自建 `.mgmt-sheet` 弹层（z-index:260）
- [app.js:1387](nantang-mobile/js/app.js#L1387)：`openMgmt('stay')` 同时开 `mgmtOverlay` + 调 `_showStaySheet`

两条路径对状态的管理不一致。

#### D（数据层）：60s 轮询静默覆写住宿数据

**文件**: [core.js:912-924](nantang-mobile/js/core.js#L912)

每 60 秒 `_mergeNTSyncData` 清空并重建所有住宿 tenant 数据，触发 `_saveShared` + storage 事件 → 其他标签页 `refreshUserUI()` → UI 刷新引起视觉闪烁。

### 修法建议

| 优先级 | 改动 | 行号 | 行数 | 效果 |
|--------|------|------|:--:|------|
| **P0** | `_calNav` 增量更新：只改月份标题 textContent + `.cal-grid` innerHTML，不动 `.cal-wrap` | app.js:1731-1735 | ~10 | 直接消闪 |
| **P1** | 轮询加锁：入住卡激活中推迟/跳过住宿数据覆写 | core.js:912-924 | ~15 | 防多标签闪烁 |
| **P2** | `_showStaySheet` 改为返回 HTML 字符串，交还 `_showCardPopup` 统一管理 | app.js:1494-1658 | ~50-80 | 架构统一 |

### 爆炸半径

- A 改动最小，仅日历翻月，零副作用
- D 仅在入住卡激活时加锁，不影响正常轮询
- B/C 回归面大，涉及全部住宿入口

## B-6 社区活动列表有内容点开后空

### 并案确认：✅ 与 A-10④ / D-12 同源

同一模式：**UI 在数据源为空/未加载时，各组件行为不一致**——部分展示本地种子数据，部分回退到空状态兜底。根在缺少跨组件的数据状态协调。

### 根因（三个并发缺陷）

#### 根因 1（P0）：`campCount` 默认值 `:1` 产生虚假计数

**文件**: [core.js:1174](nantang-mobile/js/core.js#L1174)

```javascript
var campCount = window.AppData && AppData._data.camps ? Object.keys(AppData._data.camps).length : 1;
//                                                                                     ↑ 应为 :0
```

当 `camps` 不存在时，村口卡片显示「1 个活动 · 点击查看」→ 用户点击 → `renderCommunityHub()` 正确走入空状态 → 用户看到空白。——**卡片说有，点进去空。**

这是 A-10④ 的精确并案：同一症状，同一机制。

#### 根因 2（P1）：种子营队缺少详情字段

**文件**: [app-data.js:307-309](nantang-mobile/js/app-data.js#L307)

种子营队只含展示字段（`id/name/emoji/status`），缺详情字段：

| 字段 | 状态 | 渲染结果 |
|------|:--:|------|
| `tasks` | 缺失 → `[]` | 0 个任务 |
| `builders` | 缺失 → `[]` | 暂无分配 |
| `schedule` | 缺失 → `[]` | 暂无日程 |
| `budget` | 缺失 → `{}` | 0 资金 |

`renderCampOverview()` 正确用了 `||` 默认值，不会 crash——但渲染零值空壳，用户感知等同于「空白」。

#### 根因 3（P2）：`openCampHome` / `showCampWindow` 未调 `_pushOverlay`

- [ui-camp.js:10](nantang-mobile/js/ui-camp.js#L10)：`openCampHome` 未入 overlay 栈
- [ui-village.js:40](nantang-mobile/js/ui-village.js#L40)：`showCampWindow` 未入 overlay 栈

关闭营队窗口后 `closeOverlay` 的回退行为是靠 CSS z-index 运气而非设计。

### 修法建议

| 优先级 | 文件:行号 | 修改 | 行数 |
|--------|-----------|------|:--:|
| **P0** | core.js:1174 | `:1` → `:0` | 1 |
| **P1** | app-data.js:307-309 | 种子营队补 `tasks/builders/schedule/budget/milestones` 空数组/对象 | 5 |
| **P2** | ui-camp.js:45, ui-village.js:111 | 调 `_pushOverlay` 入栈 | 2 |

### 爆炸半径

- P0：仅 `refreshVillageCards()` 村口卡片文案一行。零副作用。
- P1：影响所有查看种子营队详情的用户。加字段不破任何现有逻辑。
- P2：避免多入口打开营队时的栈混乱。低风险。

## B-7 点住宿弹出设置按钮

### 判：🟢 已消/已判明 — CSS 类名碰撞，非 G-5 引入的新 bug，G-5 仅连锁暴露

### 根因

`_showStaySheet()`（[app.js:1533](nantang-mobile/js/app.js#L1533)）和 `openAdminConfig()`（[core.js:196](nantang-mobile/js/core.js#L196)）**共用完全相同的 CSS 类名**：

| 类名 | `_showStaySheet` | `openAdminConfig` |
|------|------------------|-------------------|
| `.ci-overlay` | 全屏遮罩 z-index:9999 | 管理配置面板容器 |
| `.ci-card` | 入住卡片容器 | 配置卡片容器 |
| `.ci-head` | 入住 header | ⚙️ 地图配置 header |
| `.ci-title` | 房名+床位 | 面板标题 |
| `.ci-close` | 关闭 ✕ | 关闭 ✕ |

**没有全局 CSS 文件定义这些类**——样式全由 `_showStaySheet()` 的内联 `<style>` 块注入。

### 触发链路

1. 管理员打开地图配置面板 → `openAdminConfig()` 在 body 创建 `<div class="ci-overlay">`（配置面板 DOM 节点）
2. 管理员关闭地图 overlay → `closeOverlay('overlayMap')` **不清除** 孤立的 `.ci-overlay` 节点（[data.js:668](nantang-mobile/js/data.js#L668)）
3. 管理员打开住宿管理 → `_showStaySheet()` 注入全局 CSS `.ci-overlay{...z-index:9999...}`
4. 全局 CSS 匹配到步骤1的孤立配置面板节点 → **配置面板显示在住宿面板之上**
5. 用户看到：点住宿弹出 ⚙️ 设置

### G-5 关系

G-5（`67553fe`）修复了 `openAdminConfig` 的选择器 bug。修复前函数崩溃 → 配置面板从未成功创建 → 孤立 DOM 不会残留。修复后函数正常工作 → 残留 DOM 成为条件 → 住宿全局 CSS 触发了显示。**G-5 是正确的修复，这个碰撞是此前被 G-5 掩盖的预存 bug。**

### 自愈条件

进村（`_finishEnter`，[core.js:1039](nantang-mobile/js/core.js#L1039)）会清除所有 `.ci-overlay` 节点，离开地图页后自愈。每个 session 最多触发一次。

### 修法建议

1. **方案 A（最小改动）**：给两套代码用不同的类名前缀（`stay-ci-overlay` vs `admin-ci-overlay`）
2. **方案 B（防御）**：`closeOverlay('overlayMap')` 中一并清理残留 `.ci-overlay` 节点
3. **方案 C（根治）**：建全局 CSS 类（`theme.css`）替代内联 `<style>` 注入，避免动态样式冲突

### 爆炸半径

- 🟡 中低。仅管理员在地图页先开配置再开住宿时触发。普通用户无影响。
