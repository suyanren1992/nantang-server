## 逐条返修记录

### 🔴 D1 — _fetchCovenantStatus 判定改 r.signed !== undefined（app.js:637-642）

- **根因**：服务端 `GET /api/covenant/status` 响应键无 `ok`（真跑已证：`['sign_reward','signed','signed_at','version']`），前端 `r.ok` 恒 false。
- **修改**：`if (r && r.ok)` → `if (r && typeof r.signed !== 'undefined')`
- **效果**：判据5（换设备重登服务端权威）修复——status 直接采信 `signed` 布尔，不再绕道本地缓存。

### 🔴 D2 — _doSignCovenant 钱动提醒改读 r.reward + r.reward_granted（app.js:614-616）

- **根因**：服务端 `POST /api/covenant/sign` 响应键无 `nt_earned`（真跑已证：`['ok','signed','reward','reward_granted','balance','version','already_signed']`）。
- **修改**：`if (r.nt_earned)` → `if (r.reward_granted && r.reward)`，toast 读 `r.reward` 动态金额
- **附修**：`signedAt: r.signed_at` 改 `_todayStr()`——sign 响应无 `signed_at`（仅 status 有）
- **效果**：判据1（+10 NT 到账提醒）修复；续签（reward_granted=false）不响提醒。

### 🟡 D3 — 行为准则对接 GET /api/covenant/text（api.js:134 + app.js:161-162 + app.js:2611-2616）

- **修改**：
  - api.js 新增 `covenantText: GET /api/covenant/text`
  - app.js 新增 `_covenantTextCache` 变量，`_covenantText()` 链式回退：服务端缓存 → `_mlConfig().covenant_text` → `_defaultConfig().covenant_text`
  - `_initMap()` 启动时异步拉取服务端文本（不阻塞首屏渲染）
- **效果**：判据3（改 config 页面跟变）——签署页/公约页文本源 = 服务端权威 config，`_defaultConfig` 仅兜底。

## 太傅注（三行）

- **字段契约铁律**：前后端以响应键名为契约——服务端不发 `ok`/`nt_earned`，前端就不能读，读就是哑火。改字段名不是"优化"，是必须。

- **文本同源**：config 页面和签署页读同一个 `/api/covenant/text`，改一处两处都变——这是 D3 的核心，不是"加个 API"，是消除双份文本漂移。
