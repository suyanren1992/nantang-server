## 二、P0 级漏洞（Critical — 用户可感知 / 安全风险）

### P0-1：XSS 注入 — 用户名未转义直接拼入 onclick/innerHTML

**现状**：多处将用户名（`name`）直接拼入 HTML `onclick` 属性或 innerHTML，未用 `encodeURIComponent` 或 `esc()` 转义。恶意用户名（含 `'`、`"`、`<`、`\`）可触发 XSS 或 JS 语法错误。

**代码定位**：

| 文件 | 行号 | 问题代码 |
|---|---|---|
| `core.js` | L252 | `onclick="selectMemberPicker(\'' + name + '\')"` — name 未 encode |
| `data.js` | L328 | `onclick="doSubmit(\''+name+'\')"` — name 未 encode |
| `data.js` | L505 | `onclick="confirmWithdraw(\''+name+'\')"` — name 未 encode |
| `data.js` | L579 | `onclick="confirmSettle(\''+name+'\')"` — name 未 encode |
| `ui-archive.js` | L305-307 | `openMemberArchive(\''+encodeURIComponent(m.name)+'\',...)` — name 已 encode ✅，但 `m.name` 在 `archive-member-name` div 中未 esc()（L307 `<div class="archive-member-name">' + m.name + '</div>`）|
| `ui-archive.js` | L407 | `<span class="archive-log-text">' + item.text + '</span>` — activity_log.text 未 esc()，logActivity 写入的用户名/内容可注入 |
| `core.js` | L825 | `pickLoginUser(\''+encodeURIComponent(n)+'\')` — 已 encode ✅，但 `user-chip-name` 直接 `+n+` 未 esc() |

**触发条件**：
- 用户名含 `'` 或 `\`（如 `O'Brien`、`\test`）→ JS 语法错误，功能不可用
- 用户名含 `<script>` 或 `<img onerror=...>`（离线模式注册无服务端校验）→ XSS 执行

**修复建议**：所有拼入 onclick 的变量统一 `encodeURIComponent`；所有拼入 innerHTML 的显示文本统一 `esc()`。

### P0-2：CSS 变量双轨制 — main.css 和 theme.css 各自定义同名变量

**现状**：`main.css:2-27` 和 `theme.css:2-57` **都定义了 `:root` CSS 变量**，使用不同命名但相同语义：

| main.css 变量 | 值 | theme.css 变量 | 值 |
|---|---|---|---|
| `--green-primary` | `#3d6b52` | `--g-accent` | `#3d6b52` |
| `--green-dark` | `#2a4d3a` | `--g-accent-dark` | `#2a4d3a` |
| `--green-mid` | `#5a8a6e` | `--g-accent-light` | `#5a8a6e` |
| `--red` | `#b84c38` | `--g-red` | `#b84c38` |
| `--gold` | `#c88740` | `--g-warn` | `#c88740` |
| `--text` | `#1d2e24` | `--g-text` | `#2a2a2a` ← **值不同！** |

**冲突后果**：
- `theme.css` 用 `--g-text: #2a2a2a`（灰色），`main.css` 用 `--text: #1d2e24`（墨绿色）—— **同语义不同值**
- `core.js` / `ui-phase4.js` 大量 inline style 用 `var(--green-primary)`（main.css 定义），而 `app.js` 用 `var(--g-accent)`（theme.css 定义）—— **两套变量混用**
- `theme.css:52` 试图桥接：`--gp: var(--green-primary, #3d6b52)` — 但这只是单向兼容，`--g-*` 系列仍然不被 main.css 消费者识别
- **改色时要改两处**，且值可能漂移（如 `--g-text` vs `--text` 已经不一致）

**触发条件**：任何试图统一主题色的修改都会漏改一半。

**修复建议**：选定一套变量名（建议 `--g-*`），全局替换。main.css 的 `:root` 块删除或改为 `@import` theme.css。

### P0-3：#app 容器尺寸硬编码 — 大屏手机截断

**现状**：

```css
/* theme.css:63-70 */
#app {
  width: 400px; max-width: 100vw; height: 100vh; max-height: 900px;
  ...
}
@media (min-width: 500px) {
  #app { border-radius: 22px; height: 96vh; ... }
}
```

**问题**：
- `max-height: 900px` — 现代手机视口高度普遍 844-932px（iPhone 14/15/16），900px 限制导致底部 32-44px 内容被截断
- `width: 400px` — iPhone 14 Pro Max 宽 430px，两侧留黑 15px；iPad mini 宽 744px，两侧各留 172px
- `@media (min-width: 500px)` 加圆角 + 96vh — 在 iPad 上变成「浮窗」而非全屏，但圆角内部布局并未适配
- **底部轮播**（theme.css:314-398）用 `scroll-snap` + `mask-image` 高斯模糊遮罩，在 `max-height:900px` 截断时遮罩位置偏移

**触发条件**：在 iPhone 15 Pro（视口 852px）或更大屏手机上，底部 tabBar / FAB 按钮被挤出可见区。

**修复建议**：`max-height` 改为 `min(100vh, 900px)` 或直接移除。width 改为 `min(400px, 100vw)`。

### P0-4：任务名作主键 — 重名冲突 + 编码脆弱性

**现状**：`TASKS` 全局对象以任务名（`t.name`）为 key（`data.js`、`core.js` 全局使用）。

```javascript
// core.js:456
var t = TASKS[name]; // name = 任务名
// core.js:701
if(TASKS[name]) { var old = TASKS[name]; ... }
```

**问题**：
- 两个发布者创建同名任务 → 后者覆盖前者
- 任务名含 `'` 或 `\` → onclick 中 `encodeURIComponent` 可缓解，但 `toggleQuestCard` 中 `name = decodeURIComponent(name)` 后直接 `TASKS[name]` 查找（core.js:452-456），如果 name 含特殊字符仍可能匹配失败
- 离线创建用 `name: 'T_' + Date.now().toString(36)`（core.js:186），在线创建用用户输入标题 → 命名空间不统一

**触发条件**：社区多人发布任务，标题撞名概率不低（如「打扫厨房」「整理仓库」）。

**修复建议**：引入 UUID 主键，任务名仅作显示字段。过渡期至少在离线创建时加随机后缀。

## 三、P1 级漏洞（High — 性能 / 数据完整性）

### P1-1：AppData._saveShared 每次存盘 POST /api/data/sync_shared — 性能隐患

**现状**：`app-data.js` 中 `_saveShared()` 用 200ms 防抖后同时写 localStorage **和** POST 到服务端。

**问题**：
- 频繁操作（如连续认领任务、快速填写表单）触发大量 HTTP POST
- 60s 轮询 `_startPolling()`（core.js:308）已覆盖数据同步，**双写冗余**
- 弱网环境下 POST 排队 → 请求风暴 → Neon CU-hour 浪费
- `_saveShared` 和 `_savePrivate` 共享同一防抖计时器，混合写可能丢数据

**触发条件**：用户在弱网环境下快速操作（连续提交任务/连续鼓励）。

**修复建议**：_saveShared 仅写 localStorage；服务端同步统一走 60s 轮询。或把 POST 频率限制到 ≥5s 间隔。

---

### P1-2：跨标签同步 Object.assign 浅合并 — 数组字段被覆盖

**现状**：`app-data.js:710-724` storage event 监听跨标签同步：

```javascript
window.addEventListener('storage', function(e) {
  if (e.key === sharedKey && e.newValue) {
    var incoming = JSON.parse(e.newValue);
    Object.assign(AppData._data, incoming);  // 浅合并！
    ...
  }
});
```

**问题**：
- `Object.assign` 是浅合并 — 数组字段（如 `journal[]`、`activity_log[]`、`tasks{}`）被整体覆盖而非合并
- 标签 A 新增一条 journal，标签 B 也新增一条 → 后保存的覆盖先保存的
- `tasks` 是对象 → 整个 tasks 对象被替换，标签 A 新建的任务被标签 B 的旧 tasks 覆盖

**触发条件**：同一浏览器多标签操作（桌面端常见场景）。

**修复建议**：数组字段用 union-by-id 合并；对象字段用深合并或 last-write-wins-with-merge。

---

### P1-3：轮询退避逻辑在内部重建 interval — 潜在计时漂移

**现状**：`core.js:305-324`：

```javascript
function _pollCycle() {
  API.request('GET', '/api/nt/sync').then(...)
  // 退避
  if (_pollTimer) { clearInterval(_pollTimer); _pollTimer = null; }
  _pollInterval = (API._serverOnline === false)
    ? Math.min(_pollInterval * 2, 120000) : 60000;
  _pollTimer = setInterval(_pollCycle, _pollInterval);
}
_pollCycle();  // 立即执行
```

**问题**：
- 每次 `_pollCycle` 执行都 `clearInterval` + `setInterval` → 实际是「setTimeout 伪装成 setInterval」
- 如果 API 请求耗时 2s，实际间隔 = 60s + 2s = 62s（漂移累积）
- 服务端下线时退避到 120s → 上线后首次 sync 需等 120s 才恢复 60s（因为 `_pollInterval` 只在**下次** cycle 才重置为 60s）

**触发条件**：服务端频繁上下线。

**修复建议**：改用 `setTimeout` 递归（语义更清晰），或在 sync 成功时立即 `_pollInterval = 60000`。

---

### P1-4：离线/在线双模路径不一致 — 部分功能静默失败

**现状**：`core.js:12` `_isOffline()` 判断 `!window.API || !API.token || API._serverOnline === false`。但各功能对离线的处理不统一：

| 功能 | 离线行为 | 问题 |
|---|---|---|
| 发布任务 | `core.js:708-718` NT.createTask + 本地保存 | ✅ 可用 |
| 提现申请 | `core.js:1640-1644` 缓存到 pendingTransactions | ✅ 可用 |
| 鼓励/打赏 | `ui-archive.js:9-16` 检查 `window.NT` 后走本地 | ✅ 可用 |
| 成员沉淀面板 | `ui-archive.js:356-359` 显示「离线态无法加载」 | ❌ 无缓存 |
| 订餐 | `ui-phase4.js:283-362` — 未检离线，调用 API 会静默失败 | ❌ 无离线处理 |
| 民宿预订 | `ui-phase4.js:227-278` — `_innBook()` 未检离线 | ❌ 无离线处理 |
| 管理员审批 | `core.js:1732` showToast「离线模式无法审批」 | ⚠️ 仅提示 |

**触发条件**：用户在弱网/离线环境下使用食堂订餐或民宿预订。

**修复建议**：统一加 `_guardOnline()` 前置检查（core.js:13 已有此工具函数），或实现离线队列。

### P1-5：showToast 双签名 — 参数含义不同导致显示异常

**现状**：

```javascript
// utils.js — showToast(msg, type, targetEl)
// type = 'ok' | 'warn' | 'error'  → 浮动在页面上方
// 当传入 targetEl 时 → 内联在 targetEl 附近
```

但调用方签名不一致：
- `showToast('已送出！', 'ok')` — 2 参数，浮动
- `showToast('密码错误', 'error', document.getElementById('loginPwd'))` — 3 参数，内联
- `showToast(errors.join('；'), 'error')` — 2 参数，但消息可能很长

**问题**：长消息 + 浮动 toast → 遮挡大半个屏幕；3 参数路径的 `targetEl` 定位在某些 overlay 中不准（z-index 问题）。

**修复建议**：长消息改用 confirm/alert 卡片，toast 限制 ≤ 20 字。

## 四、P2 级漏洞（Medium — 可访问性 / 体验优化）

### P2-1：可访问性 — 几乎全部按钮缺 aria-label

**现状**：
- `index.html:112` `<button onclick="closeMyPage()" ...>✕</button>` — 屏幕阅读器读到「按钮，乘号」
- `index.html:229-237` 卡片室底部三按钮无 `aria-label`
- `core.js` 生成的 HTML 大量 `<span class="rv-ok" onclick="...">✓</span>` — 语义不明
- `main.css:279` 有 `focus-visible` 样式 ✅，但 `theme.css` 无对应规则

**修复建议**：所有 icon-only 按钮加 `aria-label`。

### P2-2：prefers-reduced-motion 仅在 main.css 声明 — theme.css 动画未覆盖

**现状**：`main.css:245`：
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; ... }
  .particle { display: none }
}
```
但 `theme.css` 中的 `scroll-snap`、`transition` 和 `mask-image` 动画不受此规则影响（`transition` 不在 `animation` 简写中）。

**修复建议**：在 theme.css 中也加 `@media (prefers-reduced-motion: reduce)` 规则。

### P2-3：登录页密码 toggle 用 span 而非 button — 不可键盘聚焦

**现状**：`index.html:63`：
```html
<span onclick="togglePwdEye('regPwd', this)" style="...cursor:pointer...">👁</span>
```
`<span>` 无法 Tab 聚焦，键盘用户无法切换密码可见性。

**修复建议**：改为 `<button type="button">` + `aria-label="切换密码可见"`。

### P2-4：archive 搜索仅按姓名精确匹配 — 中文无拼音/模糊搜索

**现状**：`ui-archive.js:370-383`：
```javascript
var match = name.toLowerCase().indexOf(kw) !== -1;
```
搜「张」能找到「张三」，但搜「zhang」找不到任何中文名字。

**修复建议**：可后续引入 pinyin.js 或 Intl.Collator。

### P2-5：iOS safe-area 覆盖不完整

**现状**：
- `index.html:111` my-topbar 有 `padding-top: max(12px, env(safe-area-inset-top))` ✅
- `main.css:133` my-tabbar 有 `padding-bottom: max(8px, env(safe-area-inset-bottom))` ✅
- `theme.css:596-600` 有 `@supports (padding: max(0px))` 兜底 ✅
- **但**：`index.html:234` 卡片室底部 bar 有 safe-area ✅，而 `main.css:293` sub-page 的 `padding-bottom: calc(80px + env(safe-area-inset-bottom))` — 80px 可能不够覆盖某些设备

**修复建议**：统一检查所有 fixed-bottom 元素的 safe-area 覆盖。

## 六、整类问题汇总

### 6.1 innerHTML 拼接模式 — 全局技术债

**规模**：grep 发现 `innerHTML = / +=` 调用 **25+ 处**（仅 core.js + data.js），覆盖几乎所有渲染函数。

**风险**：
- XSS（见 P0-1）
- DOM 重建性能损耗（每次 `el.innerHTML = h` 都触发完整 parse + layout）
- 事件监听丢失（innerHTML 替换后子元素事件绑定消失）

**根因**：纯 JS + 无框架的架构选择。短期无法根治，但可通过 `esc()` 全覆盖 + `DocumentFragment` 渐进替换。

### 6.2 inline style 泛滥 — 可维护性灾难

**规模**：`ui-phase4.js:46-83` 单个函数 `_innRender()` 内嵌 **38 行** `<style>` 字符串。`core.js` 大量 `d.style.cssText = '...'` 硬编码。

**后果**：
- 改样式需 grep JS 文件，不能用 DevTools 样式面板定位
- 暗色模式无法通过 CSS 变量切换（inline style 优先级 > class）
- 主题一致性无法保证

### 6.3 全局变量状态管理 — 无隔离

**规模**：`CURRENT_USER`、`TASKS`、`MOCK_ITEMS`、`_inn`、`_campDraft`、`_archiveActiveTab` 等 **20+ 全局变量**。

**后果**：
- 多标签/多用户切换时状态泄露（logout 函数 core.js:1805-1828 手动清理，容易遗漏）
- 无法单元测试（测试需 mock 全局环境）

### 6.4 DiceBear 头像外部依赖 — 离线/弱网风险

**现状**：`avatarURL()` 和 `profileSrc()` 硬编码 `https://api.dicebear.com/` — 所有头像加载依赖外部 CDN。

**问题**：
- 弱网/离线时头像全部 404 → `onerror` 兜底为空 emoji 或隐藏
- DiceBear API 变更（v7 → v9 已发生，`DICEBEAR_VER` 变量控制）→ 头像风格突变
- 隐私：用户头像 seed 发送到第三方服务
