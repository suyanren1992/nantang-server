## A. app-data.js:271 — 括号闭合修复

**node --check 报错**：
```
app-data.js:271
  },
   ^
SyntaxError: Unexpected token ','
```

**根因**：`_saveShared` 方法内，line 254 的外层 `if (typeof API !== 'undefined' && API.token) {` 缺少闭合 `}`。line 269 的 `}` 只关闭了内层 if（line 256），line 271 的 `},` 被解析为关闭外层 if 而非关闭 `_saveShared` 方法体 → 方法体未闭合 → `,` 在函数体内非法。

**修复**：
1. 在 line 269 后加 `}` 关闭外层 if 块（line 254）
2. `this._timerS` → `self._timerS`（与 line 247 `var self = this` 一致；方法体内 this 也是对的，但 self 更安全且与上下文风格一致）
3. `self._timerS` 移到 if 块外——无论有无 API token，都需延迟写入 localStorage（原逻辑 bug：无 token 时不设 timer → 数据不保存）

**验证**：`node --check nantang-mobile/js/app-data.js` → 绿

## B. ui-accom.js:187 — 三元运算符优先级修复

**node --check 报错**：
```
ui-accom.js:187
  '<div...font-size:1.2rem">'+isMine?'🛏️':taken?'🛏️':'🛏️'}'+'</div>'+
                                                                          ^
SyntaxError: Invalid regular expression: missing /
```

**根因**：`'+isMine?'🛏️'` 被 JS 解析为 `('+isMine') ? ('🛏️') : ...`（`+` 优先于 `?:`），且多余的 `}` 导致 `'}'` 后的 `'+'</div>` 被误解析为正则表达式字面量 `/+</div>`。

**修复**：
```javascript
// 修复前（line 187）
'<div style="font-size:1.2rem">'+isMine?'🛏️':taken?'🛏️':'🛏️'}'+'</div>'+
// 修复后
'<div style="font-size:1.2rem">'+(isMine?'🛏️':taken?'🛏️':'🛏️')+'</div>'+
```
- 三元表达式整体加 `()` 确保优先级
- 去掉多余 `}`（原代码 `'🛏️'}'` 中的 `}` 无匹配 `{`）

**验证**：`node --check nantang-mobile/js/ui-accom.js` → 绿

## C. API 契约 CI 偏差排查

### CI 报错

```
前端调后端没有: PATCH /api/new_user_tasks/{}/complete
```

### 排查路径

**1. 前端调用（api.js:171）**：
```javascript
completeNewUserTask: function(id) {
  return this.request('PATCH', '/api/new_user_tasks/' + encodeURIComponent(id) + '/complete');
}
```
deploy_check `_norm_fe_path` 归一化结果：`PATCH /api/new_user_tasks/{}/complete` ✓

**2. 后端路由（new_user_tasks.py:210）**：
```python
@router.patch("/{task_id}/complete")  # prefix=/api/new_user_tasks
```
归一化结果应为：`PATCH /api/new_user_tasks/{}/complete` ✓

**3. deploy_check.py 提取逻辑（line 271 正则）**：
```python
for dm in re.finditer(r"@(\w+)\.(get|post|put|delete)\(\s*['\"]([^'\"]*)['\"]", txt):
```
**根因发现**：正则交替组 `get|post|put|delete` 遗漏了 `patch`！后端 `@router.patch(...)` 完全不被匹配 → PATCH 路由未入 BE 集合 → 前端调用"命中后端没有"。

### 修复

`deploy_check.py:271` 正则加 `patch`：
```python
# 修复前
r"@(\w+)\.(get|post|put|delete)\(\s*['\"]([^'\"]*)['\"]"
# 修复后
r"@(\w+)\.(get|post|put|delete|patch)\(\s*['\"]([^'\"]*)['\"]"
```

附带修复：`subprocess.run` 加 `encoding="utf-8", errors="replace"`——Windows 默认 GBK 解码 node --check 的 UTF-8 错误输出（含中文路径）会 `UnicodeDecodeError` 崩溃。

### 结论

**deploy_check.py 的 bug**（不是前端/后端的问题）。正则遗漏 `patch` 方法 + Windows 编码崩溃。遵循"修闸门不修代码"铁律修复。
