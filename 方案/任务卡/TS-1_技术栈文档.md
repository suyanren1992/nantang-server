# TS-1 · 技术栈文档「建材单」（太傅主笔 · 批②地基第三份）

## 一、写什么（人话四段标准 · 三层结构）

L1 层（领域）→ L2 项（每个技术/依赖一项）→ L3 说明（人话四段）：

- **这是什么**：这玩意是干什么的，一句话人话（砚仁能复述为度）。
- **为什么选它**：南塘用它而不是别家的理由（成本/规模/已踩过的坑）。
- **用在哪**：`文件:行号` 或配置文件实证锚点——每一钉都钉在代码上。
- **怎么算好 / 不这样会怎样**：版本约束、已知风险、替代方案何时该重议。

## 二、必覆盖清单（考古起点，可增不可漏）

1. **服务端**：`server/requirements.txt` 每条依赖一节（FastAPI/uvicorn/asyncpg/SQLAlchemy/
   pydantic 等，以文件实读为准）；Python 3.14（Render）版本约束。
2. **数据库**：Neon Postgres（免费层 100 CU-小时·月限制，谏言箱在册）+ 本地 SQLite 差异
   （`with_for_update` 静默失效，宪法 §二.1 口径）。
3. **前端**：`nantang-mobile/` 静态站——无框架原生 js 的理由；`index.html` 引用清单
   （`?v=` 缓存机制，D-22 deploy_check 闸）；PWA 缓存（一页纸挂账在册）。
4. **部署运维**：Render Web Service（push main 自动部署、免费层 15 分钟休眠冷启动）+
   `server/scripts/` 三脚本（deploy_check/security_scan/arch_check）+ cron（00:05 UTC 日扣）。
5. **链上**：OP 链 NT 代币 + chain_scanner（OP_RPC_URL 依赖）+ 多签钱包规划（功能清单 F3 口径：
   设计有/概念引用/未接入）。

## 三、可证伪验收判据（丞相复核时逐条跑）

1. `server/requirements.txt` 每一行依赖在文档中有对应节：`grep -c` 对照，缺一行打回。
2. `index.html` 引用的每个 js/css 文件在「前端」层有交代（`grep -o 'src="[^"]*"' index.html`）。
3. 全文 `文件:行号` 引用**全量机检**（宪法汇编 §三.2）：全符才交付，抽样不算。
4. 砚仁测试：随机指一节，不用问术语就能读懂（人话四段齐全）。
5. 版本号与 frontmatter 一致（太傅老毛病，重点自查）。

## 四、边界

- 不写：架构设计（④架构设计文档的活，下一卡）、功能描述（功能清单已转正，指不抄）。
- 选型争议（换框架/换库）不在本卡——如实记录现状与理由，重议走朝会。
