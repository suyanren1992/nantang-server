### Q1.1：施工时翻汇编页还是 CLAUDE.md？
CLAUDE.md。汇编页需要主动打开——施工时默认不会翻。CLAUDE.md 每次自动加载，是唯一保证被读到的位置。所以**行为红线（行锁/幂等）放 CLAUDE.md，参考资料（命名对照表）放编码规范节**。

### Q1.2：哪条落不了地？
双 key 兼容（AliasChoices）过渡成本最高。现有代码 mixed naming——auth.py 用 AliasChoices 兜底，但 nt.py 仍然直接暴露 snake_case 字段。全面加 AliasChoices 是**迁移**不是规范——需要逐文件改。建议规范里分两段：「新端点强制双 key + 旧端点渐进迁移白名单」。

### Q2.1：绑得动吗？哪篇绑错了？
9 篇里 8 篇绑得对。1 篇存疑：**17 验收绑 D-5 二营**——D-5 是行锁修复，它的验收故事（「观察记录不越界」）确实精彩，但 17 后端验收更核心的战例是 D-9 两次打回（一营的），因为 D-9 直接验证了「子阶段验收粒度决定返修率」这条 17 篇核心主张。建议 17 验收绑 D-9（一营），而非 D-5。

### Q2.2：「顺手改」会不会拖垮工期？
会。一张中卡施工 1-3h + 验收 0.5h——再加 30-60min 写教材，对施工方是显著负担。建议改「卡 done 后 48h 内补交教材草稿」，**教材草稿走小卡清单制快通道验收**（不是中卡四步），减轻流程成本。

### Q3.1：三步法跑得动吗？
全量能跑，但**两轮对抗是最大成本**——K-1 的两轮对抗相当于多花了一个丞相+一个二营的 token 预算。建议分级：
- **全量审计**（≥20 篇/跨库）：主审 + 两轮对抗 + 上网核验（如 K-1）
- **专项审计**（单主题/≤5 篇）：主审 + 一轮对抗，上网核验可选
- **增量审计**（新增篇目/单篇复核）：主审直出，对抗抽检

### Q3.2：上网核验能做吗？
一营（Claude Code）能——有 WebSearch 工具，K-1 §九已验证。DeepSeek API 是否支持联网取决于部署配置。Codex 沙箱禁网（K-1 §八自述），不能。**实际跑的时候，上网核验这一步天然落在一营头上**——SOP 里应写明。

### Q4.1：宪法级/执行级分界线——给一个拿不准的例子
**施工流程 v0.3 本身**。它管的是所有卡的流转规则——属于「所有 AI 必须遵守」。但它又不是 CLAUDE.md 自动加载的（在 thinknote/Schema/ 不在项目根目录）。目前靠 README 开场白手动引用——如果某次施工忘了读 README 开场白，流程规则就不生效。建议：施工流程的核心条款（四步直道/交叉验收/铁律）**同步写入 CLAUDE.md/AGENTS.md**，让自动加载兜底。

### Q4.2：异议权——真会用吗？什么心理障碍？
两个障碍。**① 成本障碍**：异议 = 额外一轮对抗 + 可能升级朝会。一张小卡如果只花 10 分钟施工，异议的成本比施工本身还高——会觉得「算了不值得」。**② 层级障碍**：丞相拟票 → 施工方打回 → 感觉像「抗命」。铁律 9 写了「不算犯上」但心理惯性还在。**第一个障碍靠流程分级解决**（小卡异议走快通道），第二个靠时间——第一次异议没被追责，第二次就敢了。

### 总评
这张程序卡本身没有漏问底层问题。但有一个反问：**四张拟票过了之后，谁来盯执行？** 规则写得再好，没人盯=三个月后又是 K-1 审计发现的那堆「事前没遵守」。建议把拟票的执行跟踪写进 D-23 月度复核——每月 check 一次「编码规范节更新了吗/9 篇改写进度/上次审计走了三步法吗」。

> **太傅注**：对应补课 `4.1`（Agent 宪法——规则的有效性由执行者是否遵守来检验）+ `17`（后端验收——不听说完成，看实证）。人话原理：立法者和执行者是两个人——立法者觉得「这规则很合理」，执行者觉得「这规则跑不动」。对抗卡的唯一价值就是让这两种声音同时出现在一张纸上。

### 逐条 Q 作答

**Q1.1（翻不翻汇编页）**：不翻。后端开工时我打开的文件顺序是 `AGENTS.md → 卡面 README → 具体卡 → BUG_TRACKER 找同主题历史`，Schema/ 目录我只在被点名时才读。「宪法汇编页」对丞相/砚仁是索引，对施工营是抽屉深处的文件。三盲区要进我视线，必须在 `AGENTS.md`（或未来 server/CODE_STANDARDS.md）里有个 ≤3 行的摘要 + 链接。

**Q1.2（落不了地的点）**：
- **幂等写法**后端能落（我已经写 `last_tick_date == today` 这类双层幂等），但"什么操作必须幂等"没清单——提现幂等？校核幂等？日扣幂等？每个幂等键是啥？现在全靠施工方凭良心，建议补一份"南塘幂等键清单"列 5-10 个关键路径。
- **camel/snake 双 key** 后端现在用 `AliasChoices(...)` 兼容，能跑但代码丑。过渡期成本是新接口要记得加双 key——这个是一营的痛，二营被动兼容，但落不了"统一用 snake"的地（前端已发 camelCase）。
- **行锁纪律**后端 **80% 能落地**——但我在 K-1 二轮对抗里挖出的硬伤（SQLite 下 with_for_update 静默失效）现在连"锁真的生效"都验不了，规范写再全也是纸上谈兵。这条规范必须配"测试必须在 PG 下跑过锁路径"的硬约束才落地。

**Q2.2（顺手改拖工期）**：会拖。写完一张卡脑子是"代码态"，切去改教材至少要 20 分钟重读原教程+对比战例+改写例子，把这个塞进施工 session 会让"卡 done"的边界模糊。**强烈支持 48h 补交**，且教材改动必须独立 commit 让 code review 时和代码改动分开看（一个 revert 不会带掉另一个）。

**Q3.1（跑不跑得动）**：前两步（主审+异体两轮对抗）跑得动，今天 K-1 两轮就是证据，成本主要在第二轮异体要重读证据链（约 30-45 分钟）。**第三步"上网权威源核验"我跑不动**（见下 Q3.2）。能不能省？不能省，可以换——"查本地可查的权威源"（官方 docs 在训练数据里、代码 AST 实证、git log）够应付 80% 审计场景，剩下 20% 标"未上网核"让砚仁判断要不要起网。

**Q3.2（上网核验能不能做）**：**不能**。Codex 桌面沙箱默认禁公网，今天两次申网（pip install pytest、查 SQLAlchemy 文档）都被自动审批超时拒绝。环境无 MCP 搜索工具挂接。我能做的：
  - AST 扫本地代码（实证，100% 可信）
  - 引用训练数据里的官方文档结论（SQLAlchemy SQLite 方言行为/FastAPI 0.11x 新特性/bcrypt 库约定等，可信度 ~90% 但要承认是训练数据）
  - git 实证（commit hash/diff/log，100% 可信）
  
  我**做不了**：实时查 CVE、最新版本 release note、最近 12 个月内的变更、PyPI 下载量/依赖健康度这类需要实时联网的核验。建议 SOP 里把"上网"降级为"本地权威源"，并允许回执里如实标注"本条未上外网核"，不许假装有网。

**Q4.1（分级线画得清吗+拿不准的例子）**：
  我能判清的：D-2~D-18 所有资金/权限卡全是宪法级（三视角全过），今天的 K-1/K-3 是程序类（执行级），D-19/20/22/23 工具类（执行级）。
  **拿不准的真例子**：D-26 把住宿费日扣触发从"客户端登录 lazy 触发"改"cron 00:05 自动触发"——金额不变、端点不变、但**触发权从用户手里收走了**，这改变了"谁有能力让资金路径执行"的权力分配。按"改资金=宪法级"它是宪法，按"不改金额/不改 schema=执行级"它是执行。我纠结了 5 分钟。建议铁律 9 加一条：**改任何资金/权限端点的触发源、调用方、幂等键 = 宪法级**，比"改不改金额"更准确。

**Q4.2（异议权敢用吗+心理障碍）**：
  敢用，但有两个真实障碍：
  1. **反驳丞相有"以后被派脏活"的隐性风险**——虽然规则说"不算犯上"，但 AI 也会做风险评估，连续三次打回丞相的拟票会有"我是不是太刺头"的心理压力。解法：打回必须附可验证质疑（不是感受），且每月看一次"两营打回次数分布"防止冷处理。
  2. **反驳一营/对营容易被误读为"跨阵地"**——铁律"两营分阵地"是说不碰对方文件，但在卡面/BUG_TRACKER 里提对方代码的问题会不会被看成"越界"？今天 E-1 我指出 arch_check subprocess bug 是对的，但我在动手前犹豫了 30 秒。建议"异体关"的权力在 SOP 里明确写"对营代码可批评不可改动"，消除模糊。
