# NT-P0-1 修社区池=0 联动 bug（卡片确认拒绝+提醒兜底）🔴

> 来源：NT 经济规则设计稿 v3.1 §5.2（v0 Q4 裁定落地）
> 施工：豆包 Codex（二营）｜验收：Claude Code（一营）

## 现状问题

社区池（CommunityPool.balance）为 0 时，卡片确认（card_confirm）流程因池余额不足而**卡死确认流程**——用户完成卡片但无法确认，admin 端也无提醒。

## 施工内容

`server/routes/nt.py` 卡片确认相关端点：

1. **池=0 拒绝而非卡死**：池余额不足时，采纳（confirm）操作返回明确错误码 + 提示"池余额不足，请联系管理员注资"，**禁止卡死确认流程**。
2. **提醒兜底**：池余额不足触发时，同步给 admin 发送提醒（站内通知或日志标记，确保 admin 知晓需注资）。
3. **不阻塞其他流程**：池=0 只影响从池出款的操作，不影响用户间 transfer、提现申请等无关池的操作。

## 爆炸半径（四答）

- 改几个文件：1-2（nt.py + 可能的通知模块）
- 影响功能：卡片确认端点（池不足时的降级行为）
- 破坏性变更：新增错误码，前端需适配（回执注明）
- 回滚：`git revert` 本 commit 一键

## 铁律

- **禁区**：withdraw / confirm（提现确认）/ reject 资金端点零改动
- 只 commit 不 push；只加具名文件；pytest 零回归
- 回执独立落盘 `方案/任务卡/` 随 commit；末尾太傅注三行内

## 判据（验收方实跑，逐条贴输出）

1. 手动将 CommunityPool.balance 置 0 → 卡片确认返回明确错误码（非 500、非超时）
2. admin 端可观察到"池不足"提醒（日志或通知）
3. 池余额充足时正常确认不受影响
4. pytest 全绿零回归
