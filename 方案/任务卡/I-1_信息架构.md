## 一、病灶（丞相初判，考古证实或证伪）

1. **方案/ 目录混层**：20+ 份 2026-07-22 双轨时代散文件（`总执行方案`/`延期执行方案`/
   `校核室完整实现方案`/`换房计费审查`/`UI改造设计_田地冰箱大扫除` 等）与五份真源混在一层，无归档无索引。
2. **入场协议信噪比低**：两营开工读 README+备忘录+总则+流程+入场令，当日真正要用的只有几行；
   丞相换窗口恢复态势要读全文（瘦身前 260 行）。
3. **Obsidian 原生能力未用**：无双链、无 MOC（目录总目页）、无分区；查找靠文件名记忆。
4. **全院找规矩靠猜（新增，实证见下）**：规矩散在 Schema/、方案/、Log/ 三处，
   高频规矩（呈批格式）埋在风格指南 L26，入口必读层无锚点——人找东西没有「一个门」，
   AI 换窗口找规矩靠逐层指路链。

| 查法 | 结果 |
|---|---|

## 三、设计原则（砚仁 19:04-19:06 确认：当初准则拿来用为主，升级一处）

> 当初建库谨慎路径——「分圈、增量、只进不退」——经 T-1/T-3/T-4 三次实战检验，即本卡施工法。

| 当初准则 | 出处 | 本卡用法 |
|---|---|---|
| 领域靠 `[[链接]]` 到 MOC 表达 | Schema/元数据规范.md:46,:97 | 总目页 = 规范预留未建的 MOC，**补欠账非立新法** |
| 存量分批：dry-run 20 样本 → 砚仁验收 → git 回滚点 → 全量 | Schema/元数据规范.md:99 | 先核心圈（Schema+方案+Log）建总目，小样呈批后再扩全院 |
| 只禁新增，不追溯存量 | T-4（施工流程变更记录） | 总目/lookup **只增不动**：不移一个文件、不改一字正文 |
| 真身+指针 | T-3 真身制 | lookup 只回门牌（路径:行号），不复制内容——查到门牌自己去读 |
| 在册宇宙分圈 | T-1 闸 | 总目分圈：核心圈先进，豁免区（Daily/存档）后进 |

**升级一处（MOC 保鲜机制，规范原文未覆盖）**：总目页头部带锚点
`基于 commit \`xxxx\` 实证 · 日期`（抄架构图作业）；**闸加黄灯项「总目页锚点落后 → 提醒」**
——改闸判据 = 立法，随本卡方案呈批走法定程序，不私改。

## 四、考古项（二营，只读，证据链入卡）

1. **文件盘点**：`方案/` 全量文件清单——逐份判定：真源 / 任务卡 / 在途 / 历史归档 / 墓碑候选，
   每份附「最后被引用于哪份文档或哪张卡」的证据（`grep` 全仓库+thinknote 互引）。
2. **引用图**：五份真源 ↔ 任务卡 ↔ 备忘录 ↔ thinknote 侧的互相引用关系（谁引用谁，
   拆开后哪些链接会断）。
3. **入场成本实测**：一营/二营/丞相各席位开工实际要读的文件与行数，列出「必读/选读/不读」三档。
4. **墓碑判定**：07-22 散文件逐份给「归档 / 删除候选 / 仍有活引用」结论——删除候选一律只移不删
   （入 `方案/归档/`），铁律 5 不破。
5. **全院索引考古（新增，笔记库线）**：24 个领域索引逐份盘点（维护者/新鲜度/覆盖域）；
   高频规矩清单（各席位每月实际要查的规矩 Top 10，从 Daily 心跳与回执统计）——
   作为 lookup 接口的首批收录范围。
6. **T 系列接口现状**：T-1 闸判据/T-3 真身指针/T-4 方言清单与本卡的衔接点
   （哪些直接复用、哪些要随方案升级）。

## 五、双交付物定义（砚仁 18:51 谕）

### 交付物一 · MOC 总目页（人用）

- 分圈建设：**核心圈先行**（Schema 规矩区 + 方案真源区 + Log 台账区），每圈一页 MOC，
  Obsidian 双链互挂；豁免区（Daily/存档/领域子库）后进，扩圈走呈批。
- 项目线分区沿用原案：方案区（真源）/ 卡区（任务卡）/ 战场区（备忘录+一页纸+BUG_TRACKER）/ 归档区。
- 每页头部带实证锚点（见第三节升级条）；人话四段标准（是什么/为什么/用在哪/怎么算好）。

### 交付物二 · 机器 lookup 接口（AI 用）

- 一份**机器可读门牌文件**（`Schema/lookup.md` 或同位 YAML，格式随方案定）：
  「我要 X（呈批格式/心跳格式/发卡流程/验收判据…）→ 去哪读（路径:行号）」，
  只放指针不放正文（真身+指针原则）。
- 入口协议挂它：各席位开工「读本席入场令 + 查 lookup」替代「读 N 份全文」；
  高频规矩 Top 10（考古项 5 产出）为首批收录。
- 保鲜同锚点制；闸黄灯随立法。

## 六、方案要求（考古后丞相设计，呈砚仁拍板）

- **入场减负**：每席位开工只读本圈 MOC + 本席位入场令 + lookup；备忘录保持瘦身制（当前批+指针）。
- **口径收编**：拆分后的 frontmatter/命名/双链方言挂 T-4 规范 v1.1 一并定稿。
- **不动**：五份真源内容本体、git 历史、vault_gate 判据（改闸走立法）、任何存量文件位置
  （总目/lookup 纯增量，分批呈批后才扩圈）。

## 七、可证伪验收判据

1. 考古回执附全量文件盘点表（每份文件一行：判定+证据），无证据行打回。
2. 引用图覆盖五份真源全部出入引用，抽样 5 条 `grep` 可复现。
3. 方案呈批时附「拆分前后：一营开工要读多少行」对照数字。
4. **lookup 实测（新增）**：全新窗口 AI 只给 lookup 文件，找「三段式」「心跳格式」
   「发卡流程」三个门牌，**一跳即中（≤1 次跳转）**，实测记录入卡。
5. **总目保鲜（新增）**：总目页锚点机制 + 闸黄灯提案随方案呈批，立法通过后落闸。
6. 施工（批③拍板后）：`python server/scripts/deploy_check.py` + vault_gate 全绿；
   断链检查脚本（一次性 stdlib）零断链。
