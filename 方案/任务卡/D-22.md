# D-22 部署总检脚本（二营）

> 来源：对照体检病根「部署总检缺失」+ 07-24 asyncpg 部署事故教训。
> 施工：豆包 Codex｜验收：Claude Code

## 施工内容

写 `server/scripts/deploy_check.py`（纯 stdlib），本地/部署前一条命令跑四检：

1. **依赖对账**：`requirements.txt` 清单 vs 代码实际 import——照 asyncpg 事故模式，
   代码里 import 了但 requirements 没有的 → 报红（已知例外列白名单）
2. **?v= 一致性**：`index.html` 引用的 js/css 版本号 vs 文件实际 mtime——
   改了文件没升版本号 → 报黄（缓存铁律机检化）
3. **环境变量清单**：代码里 `os.environ`/`getenv` 读取的变量汇总成表，
   对照 Render 必需项（DATABASE_URL/JWT_SECRET/INVITE_CODES 等）标注哪些必须配
4. **部署后冒烟**：curl 模式——站点 200、`/api/nt/sync` 401、index.html 版本号回显
   （部署后手动跑或接 Render deploy hook）

## 判据（验收方实跑）

1. 干净 venv 里跑出完整报告
2. 故意从 requirements.txt 删掉 asyncpg → 第 1 检报红；改 js 不升 ?v= → 第 2 检报黄
3. 此后每次 push 前跑一遍写进施工流程快通道（丞相补条文）
