## ② 实测关 ✅（真跑贴输出·非静态扫描）

### 2.1 服务端两路径回包（临时 SQLite + ASGITransport 直连 main.app）

脚本 `.scratch/p1_2_final_server.py` 实跑输出：

```json
{
  "retract_resp": { "ok": true, "status": "草稿", "refunded": 3 },
  "draft_sync_all_raw": "草稿",
  "draft_nt_sync_raw": "草稿",
  "retreq_sync_all_raw": "撤回申请中",
  "retreq_nt_sync_raw": "撤回申请中"
}
```

**事实**：撤回未领任务 → retract 返 `{ok, status:草稿, refunded:3}`；`sync_all` 与 `/api/nt/sync` 两路径回包**原始态都是中文**（草稿 / 撤回申请中）。
**推论**：两路径服务端一致传中文 → 前端两个 merge 函数**都必须归一**，缺一即漏。这正是 D6 的必要性依据。

### 2.2 前端归一逻辑真跑（node 模拟 D6:895-896 对上述原始态）

```
撤回未领·sync_all : 原始[草稿]     -> 归一[draft]             -> renderDrafts可见
撤回未领·nt_sync  : 原始[草稿]     -> 归一[draft]             -> renderDrafts可见
撤回申请·sync_all : 原始[撤回申请中] -> 归一[retract_requested] -> 管理员审核区块可见
撤回申请·nt_sync  : 原始[撤回申请中] -> 归一[retract_requested] -> 管理员审核区块可见
```

**推论**：两路径回包经 D6 归一后均落 `draft`/`retract_requested` → 撤回后草稿箱首帧可见，60s+ 轮询一圈（走 `/api/nt/sync`→`_mergeNTSyncData`）仍归一为 draft → **草稿箱不蒸发**；撤回申请中同理，管理员审核区块不被轮询冲掉。
