## 太傅注（三行）

- **对称操作是第一课**：两个长得像双胞胎的 `mergeXxx` 函数、同一批 server→client 数据、同一种中文态问题——修第一个时顺手 grep 第二个，本该一轮过。漏了对称就是漏了一个同步通道，状态在两天入境口岸之间来回被冲。
- **60s 蒸发 = 时序陷阱**：sync_all 瞬间归一 → 用户看到草稿箱正常 → 满意 → 60s 后轮询冲回中文 → 刷新页面发现没了 → "刚才明明在的！"——这类延迟 bug 比即时 bug 难抓十倍，因为"第一眼看起来没问题"。
- **归一到头 = 共享常量文件**：每次 sync 都做字符串翻译是治标。治本是前后端共享 `TASK_STATUSES` 作为唯一真相源——前端直接用 key（draft/open/submitted）、服务端存相同的 key、sync 只传 key 不传 value。本波挂账，架构债。
