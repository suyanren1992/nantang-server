## 修一 · 「丞相不施工」但书 — 对抗

### 🔴 撞墙点 1：三条件的「认定权」没有定义，但书成自我授权后门

**原文声称**：三条件须同时满足——①客观做不了 ②处方已实证 ③制衡不断。

**问题**：修款全文没有写**谁认定**条件①②③满足。默认是丞相——因为发卡/裁定是丞相的宪法职能（操作总则.md:41）。但在亲工场景中，丞相同时是：

- 条件①的认定者（"二营没 PG 串，客观做不了"）
- 条件②的处方者 + 刮卡验证者（BUG_TRACKER.md:1990-1994）
- 条件③的实跑验收者
- commit 的执行者

**实证**（K-2 首案角色重合，`git log --all --oneline -- server/tests/test_pg_locks.py`）：

```
ee971b2 fix(K-2): ...丞相亲工(砚仁18:40授权破例,新规首案)
8b8def2 fix(K-2)+docs: 第三轮——...二营施工,丞相代commit
9d36bac docs(BUG_TRACKER): K-2判据④重跑仍FAILED入档——...二次打回
052fb90 fix(K-2): 返修——...二营返修,丞相代commit
```

BUG_TRACKER.md:1990 → 丞相"坐实第三层根因" → :1992 丞相刮卡实证（"副本验证，不动仓库文件，验毕已删"）→ commit ee971b2 丞相亲工 → :2009 处方精确到行 → :2010 丞相当场实跑 3 passed。

**四个角色合于一身**：处方发现者 = 刮卡验证者 = 亲工执行者 = 判据验收者。一营复验（BUG_TRACKER.md:2022）明确写了"一营无 PG 串，不重跑"——只做 diff 对账和文档自洽审查，不是独立验收。

**最可能撞墙场景**：未来任何施工营卡壳时，丞相只需判定"客观做不了"（缺 API key / 测试环境 / 工具），即可刮卡→处方→亲工→自验闭环。施工营变成盲改靶场 + 事后复读 diff 的图章。

**建议**：条件①「客观做不了」的认定不能由丞相单方——至少加一条：施工营书面确认"本营确实无法执行"（以回执形式写入卡或 BUG_TRACKER），即**施工营主动认领"我做不了"**才算。不能是丞相代施工营说"你做不了"。

### 🔴 撞墙点 2：刮卡验证的「副本」不归档，违反铁律 2（口说无凭）

**原文声称**：条件②"处方已实证，且经刮卡/副本验证过"。

**事实**：BUG_TRACKER.md:1992 写"刮卡实证（副本验证，不动仓库文件，**验毕已删**）"。副本没有 commit，没有留痕。事后审计「处方是否真的刮卡验证过」→ 零证据，只剩丞相自述。

这与铁律 2（施工流程.md:28 "结论必挂锚点（路径:行号 / 命令实跑输出 / git commit），无锚点标「待核」"）直接冲突。刮卡验证是亲工的前置条件，但这个条件本身的锚点是什么？没有。

**可验证检查**：

```bash
# 全仓搜索刮卡验证的实证残留
grep -r "刮卡\|副本验证" BUG_TRACKER.md
```
→ 只有丞相自述段落，无任何文件/commit/输出可证伪。

**建议**：条件②加"刮卡副本须 commit 到 `.scratch/` 目录并引用路径"——不在正式代码路径，但可审计。或者至少要求刮卡运行的命令+输出贴入 BUG_TRACKER（锚点义务）。

---

### 🟡 撞墙点 3：「丞相亲工」标签不防越界，一次破例→惯例滑坡

**原文声称**：commit 注明「丞相亲工」，亲工须入档（BUG_TRACKER+Daily 注明授权原话与三条件符合性）。

**事实**：标签是事后追溯线索，不是事前防越界闸门。写着「丞相亲工」的代码和写着「二营施工」的代码，对生产系统的影响完全相同。K-2 首案亲工的是测试文件（test_pg_locks.py）——这是可接受的低风险破例。但修款没有写**亲工范围边界**。

一旦入宪成为合法路径，"测试脚手架"很容易滑向"配置文件"再滑向"业务端点"。明天的丞相可能说"这个资金锁的 fix 也是二营没环境做不了的"——同样的三条件逻辑，同样的自闭环。

**建议**：至少加一条收束闸——「丞相亲工」限定文件类型白名单（测试 `tests/` / 文档 / 配置 `.env.example` / 构建脚本），不得触及业务端点（`routes/*.py`）、数据模型（`models.py`）、资金路径。这是可机检的约束（`git diff --name-only` 白名单），不靠人判断。白名单外需施工营执行。

---

### 🟡 撞墙点 4：K-2 的「客观做不了」实为权限问题，不是能力问题

**K-2 事实**：二营缺 PG 连接串 → 盲改三连败。丞相有 PG 串 → 亲工闭环。

**问题**：Neon Dashboard 开分支 → 砚仁给连接串 → 二营就能跑。这个链条里，真正"做不了"的是"没有连接串"，不是"没有能力修"。如果丞相当初**把 PG 连接串给二营**而不是自己亲工，二营能不能修？K-2 前两轮打回（构造错/循环错位）二营都修对了——只是第三轮需要真 PG 实跑才能发现装饰器覆盖和 FK 落库序。

也就是说：**不是二营做不了，是二营没有做这件事的环境**。修款应该区分"客观能力缺陷"和"环境权限缺失"——后者解法是补环境，不是换人。

**建议**：条件①"客观做不了"改定义为两档——A 档「环境缺失」（给串/给权限后营能修）→ 解法是补环境，不触发亲工；B 档「能力缺失」（有环境仍修不了）→ 才可能触发亲工。K-2 属于 A 档，不应成为亲工先例。

## 修二 · 入口协议加呈批格式锚点 — 对抗

### 🟡 撞墙点 1：闸查不了的规矩入宪法，等于宣誓不执法

**原文声称**：入口协议加第 5 条——呈批=三段式（🎯→🤝→📎），复制内容标「📋 整段复制」。

**问题**：闸（vault_gate.py）目前只查心跳格式（`[HH:MM]` 正则——操作总则.md:34）。三段式格式是**语义层**内容——闸无法机检「有没有 🤝 行」「有没有 📋 代码块」。闸查不了的规矩入宪法 → 没有执法 → 又回到"砚仁不满意=最强执法"（风格指南.md:11），等于没升级。

**可验证实证**：

```bash
# 闸目前查的格式项
grep -c "🤝" 技能与工具/scripts/vault_gate.py
```
→ 预期：0（闸不查三段式结构）。修款作为入口协议第 5 条加入宪法后，闸不查它——等于一条无法执法的宪法条款。

**建议**：不单独立第 5 条宪法级条目。在现有入口协议第 4 条末尾追加半句锚点指路——"呈批走三段式（🎯→🤝→📎），详见风格指南.md 提案 f/g"。格式规范本身留在风格指南（榜样层），入口协议只管指路。不膨胀宪法、不创没法执法的法、同时解决"找不到"的问题。

---

### 🟡 撞墙点 2：案例的根因不是"格式没入宪"，是"指路不在视线内"

**修款案例**：丞相换窗口后丢格式，翻 4 个文件才找到三段式。

**三段式现状**：早已写在风格指南.md:27-28（提案 f/g），入口协议只写了一行指路"旧规风格类...榜样非法律"（操作总则.md:48）。问题是入口协议的正文四步里没有"呈批格式"的关键词锚点——AI 读入口协议时视线扫不到"三段式"三个字。

**根因不是格式没入宪，是入口协议的指路不醒目**。解法是在入口协议正文里加锚点词（不是另立第 5 条宪法级条目）。

---

### 🟡 撞墙点 3：「📋 整段复制」代码块没有防嵌套歧义

**原文声称**：要复制转贴的内容放独立代码块标「📋 整段复制」——块内即所贴，块外即所述。

**问题**：如果丞相要转贴的内容本身是一段**包含代码块的 markdown**（比如宪法修正案原文，里面就有代码块），就会出现 markdown 代码块嵌套——外层的「📋 整段复制」代码块和内层的内容代码块冲突。Markdown 不支持任意深度代码块嵌套。

**实例**：假设丞相呈批一段 shell 命令：

````markdown
📋 整段复制
```
PG_DATABASE_URL=postgres://... pytest server/tests/test_pg_locks.py -v
```
````

→ 外层和内层都用三个反引号 → 渲染器会在第一个 ``` 处关闭代码块 → 剩余内容裸奔。丞相必须知道切换外层为四个反引号——但修款没有写这个细节。

**建议**：风格指南.md 提案 g 补一句"若内容本身含代码块，外层用更多反引号"——或者入口协议锚点不写细节，只指路到风格指南。
