## 三、H-5 误诊留证（重点，请丞相复核）

**卡面 H-5 修法 `.where(ActivityLog.user == user.id)` 在现行代码下无法执行、且违背设计意图。三条实证：**

1. **模型无 user 字段**：`server/models.py:174-179` `ActivityLog` 仅有 `id / time / type / text`。照抄会直接 `AttributeError` 崩溃。
2. **写入端不记归属**：`data.py:133 add_activity_log` 与 `tasks.py:266 _log_activity` 建 `ActivityLog` 时都不写"谁产生"。即使加字段，存量与写入端全为 `None`，普通用户将什么都看不到。
3. **数据本质是全站公开流**：内容为 `role_change` / `task_retract` / `task_unclaim` 等系统事件；前端 `core.js:1309`「最近动态」为全体展示，本无"个人所有"概念。且 GET 端 `data.py:126` **已有** `get_current_user`，未登录本就进不来（判据"无鉴权暴露"实为不成立）。

**裁定**：判据2「普通用户只看自己的」在现行 schema 下无法满足，且与设计意图冲突。按案A（用户已批）**判为误诊、留证不改码**。若日后确需按用户过滤，须另开卡做 schema 扩展（加 user 列 + 写入端透传 + 迁移旧数据），属 🔴 成本，不宜夹带进本安全补丁。
