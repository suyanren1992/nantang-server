## 3 个实施备注（非 P0，施工时明确即可）

### 备注 1：trust "劳动涨 5-10" 粒度未定义

§十 #2 说"劳动涨 5-10"，但未区分哪种劳动涨 5、哪种涨 10。现行代码有三种涨分路径（`nt.py:692` 单人 +2，`nt.py:735` 多人 +5，`nt.py:744` 发布者 +3）。施工时需明确映射：

```
建议（施工卡里写死）：
  单人任务完成 → +5
  多人任务每个执行者 → +8
  发布者（任务被完成） → +10
  提现 → -5
```

**施工卡一行可解决，不阻塞 v0.3.2。**

### 备注 2：last_active_at 恢复行为未定义

§十 #3 说离开 > 30 天"失效治理权"。但用户回来后（day 36 翻牌 onsite），治理权是**自动恢复**还是**需重新累计**？

```
场景：用户 A 离开 35 天
  Day 31-35：治理权失效（Tenancy 仍 active，但 last_active > 30 天）
  Day 36：回到南塘，翻牌 onsite → last_active 更新为 Day 36
  → 治理权自动恢复？还是需重新等 3 周（提案权）？

建议：投票权自动恢复（满足三 AND 即刻生效）；提案权继续用 first_checkin_date 算（不受影响）
```

**施工卡一行可解决，不阻塞 v0.3.2。**

### 备注 3：cron 阻断后解锁机制未定义

§十 #5 说"3 次告警 = 阻断日结"。但没有定义**谁、如何、何时解锁**：

```
建议（施工卡里写）：
  阻断后 → admin 手动调 POST /api/system/daily-tick?force=true 解锁
  或：连续 2 次手动日结成功 → 自动解除阻断
  阻断期间：前端 banner 显示"系统维护中，涉钱功能暂停"
```

**施工卡一行可解决，不阻塞 v0.3.2。**
