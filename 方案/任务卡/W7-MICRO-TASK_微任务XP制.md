# W7-MICRO-TASK · 微任务系统（XP 制）

## 一、为什么开

NT-DECIMAL 回滚后，0.5 NT 微任务不可行。皇帝 08-02 选 B：微任务给经验值（XP），不给 NT。

**本卡 = 给现有校核闭环加上 XP 出口。** 校核通过 → 校核者得 XP，不碰 NT。

## 二、做什么

### MICRO-A · User 模型加 XP 字段

`User.xp`（已有 `experience_value`，复用或改名）。如果 `experience_value` 语义够用就直接用，不新增字段。

### MICRO-B · 校核接口加 XP 发放

现有校核端点（`/api/nt/verify` 或类似）通过后，额外 +XP：
- 校核 1 次 = +10 XP
- 连续校核 3 天 = +15 XP（奖励）
- 同一任务多次校核 = 不加（幂等）

### MICRO-C · XP 排行榜

`GET /api/xp/leaderboard?scope=weekly` → 本周 XP 排行

### MICRO-D · 测试（≥3 条）

1. 校核通过 → XP +10
2. 同任务重复校核 → XP 不重复加
3. 排行榜返回正确排序

## 三、不做什么

- 不发 NT
- 不做 XP→NT 兑换（那是后续机制卡）
- 不做前端 UI（留给 MICRO-TASK-FE）
- 不接入打赏

## 四、接口预留（给后续卡）

- `POST /api/xp/grant` 端点独立，后续打赏/签到/晨练都可调
- `User.xp` 字段与 `nt_balance` 完全解耦

## 五、影响面

| 问 | 答 |
|---|---|
| 调用方 | 校核端点（+XP 发放） |
| 被依赖方 | XP 排行榜前端 + XP→NT 兑换 |
| 关联测试 | `test_micro_task.py`（+3 条） |
| 回滚路径 | 独立文件 + 独立模型字段，可单独 revert |

---

**太傅注**
- 补课：XP 系统 = 劳动积分，NT 系统 = 经济货币。解耦后各自独立演进——XP 改规则不影响 NT 守恒，NT 改规则不影响 XP 公平。
- 一句原理：校核 = 验证劳动真实性。验证通过给 XP = 承认劳动价值，但不发 NT = 不增加货币供应。比直接发 NT 更保守、更安全。
- 不这样做会怎样：直接给微任务发 NT → 0.5 NT 精度问题（回到 NT-DECIMAL 的坑）→ 回滚 → 重来。
