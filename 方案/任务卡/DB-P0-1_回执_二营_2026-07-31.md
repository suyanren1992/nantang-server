## 关键设计决策

- **写路径放在 `get_current_user` 而非全局中间件**：所有 auth 端点已有此依赖，自动覆盖 104 个端点。同日跳过（`last_active_at != today`），每用户每日仅一次写库。
- **严格不通过**：无 `last_active_at` 记录的用户投票权 `eligible: false`（旧逻辑默认通过）。新用户在首次 HTTP 请求后自动获得 today 标记 = 投票权生效。
- **投票权 HTTP 集成特性**：发了请求 = 活跃 = 有投票权。旧 inactive 测试改判为 True（因 HTTP 请求触发 activity tracker）。

## 太傅注

流水不腐，户枢不蠹——治理权的"活跃"不是存在性判断，而是时序性证据。`get_current_user` 作为所有 auth 端点的统一入口，是天生的活跃探头。同日跳过是写库成本的妥协，也是"发了请求就是活跃"的设计意图的精确表达。
**不活跃的用户不会发 HTTP 请求——这恰好是投票权应失效的时刻。**
