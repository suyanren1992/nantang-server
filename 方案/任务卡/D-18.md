## 施工内容（四项）

1. **M-13 校核驳回接服务端**：`verifyAction` reject 分支（app-data.js:349-360）改 HTTP POST
   `/api/nt/verifications/{id}/reject`（body `{reject_reason}`），照 approve 分支的 .then/.catch 结构；
   api.js 加 `rejectVerification(id, reason)`。UI 零改动（按钮与原因 prompt 已就位）
2. **M-14 提现接服务端**：`submitWithdraw`（core.js:1414）改调 `POST /api/nt/withdraw`；
   `pendingTransactions` 切服务端权威——本地队列降级为**离线缓存**：失败时入队、恢复后重放，
   界面余额以 `/api/nt/sync` 服务端值为准，杜绝"界面扣了服务端没扣"回弹
3. **M-15 admin 审批切服务端 + cashout 下线**：review 面板改拉 `/api/admin/withdraws/pending`
   为权威源；approveTx/rejectTx 的 cashOut 分支改调 `/withdraw/confirm`、`/withdraw/reject`；
   **cashout 端点下线**：前端零入口（本来就没接），server 端标记 deprecated 注释保留（二期删）
4. **M-17 退房按钮**：住宿面板加「退房」→ `POST /api/accommodation/checkout`（app.js ~25 行 + api.js ~3 行）

## 铁律

- 改 js 同 commit 升 index.html `?v=`；只 commit 不 push；一次到位但分 4 个 commit（每项一个）
- api.js 新方法风格照既有 createDepositIntent/topUp

## 判据（验收方实跑）

1. 驳回一条校核 → 服务端 Verification 状态变 rejected、retry_count+1（直查库或接口）
2. 发起提现 → 服务端 withdraw ledger 有 pending 记录、pool.frozen 增加；刷新/换设备余额不回弹
3. admin 面板看到的 pending 列表 = 服务端 `/withdraws/pending` 返回；confirm 后 ledger 状态变更
4. 退房 → tenancy 状态 checked_out、角色降级、欠费结算正确
5. 断网提交提现 → 本地入队；恢复网络后自动重放成功
