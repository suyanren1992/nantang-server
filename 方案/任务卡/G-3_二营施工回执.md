## 二、迁移策略（破坏性变更明示）
- **存量已扣不回滚**：旧 `accommodation_fee`(settled) 流水保留，历史扣款不追溯退回。
- **存量欠费并入退房结算**：`_settle_tenancy` 汇总 `due + 存量 debt`，一并结算；不足留存 `debt`（不清零→可追缴/展示）。
- **新列 default 0**：测试 create_all 自动含；生产走 database.py ALTER 守卫（列已存在则跳过）。
- **可回滚**：置 env `ACCOMMODATION_DAILY_MODE=deduct` 即切回旧日扣分支（代码保留）。

> **太傅注**（补课 3 行）：
> ① 会计原理——住宿费从「每日现金扣」改「应计记账（accrual）」：日增 `accommodation_due` 只挂账不动钱包，退房才「一次性结转」扣款入池，钱随单走对账等式因转移守恒恒平（补课：《社区资金系统_执行手册》池-账-单三层 + 复式记账 accrual vs cash basis）。
> ② 为何守恒——`due/debt` 是「未来应付」不算已发行 NT，故不进 total_system；结算日 user 减多少 pool 加多少，两侧抵消 → 系统总额不变（这是判据5的真不变量，绝对等式只在无注入 seed 时成立）。
> ③ 可回滚设计——mode 开关（accrual/deduct）+ 新列 default 0 + 存量不回滚，是「破坏性钱流改造」的安全垫：出事一个 env 切回旧日扣，历史流水零污染。
