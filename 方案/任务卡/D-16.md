# D-16 data.py 阵地查漏（一营小卡）

> 来源：D-11 勘察额外观察 1 + M-16。data.py 属一营 D-8/D-12 阵地，二营回避。
> 施工：Claude Code｜验收：豆包 Codex

## 施工内容（两项）

1. **LIKE 通配符第三处**：`server/routes/data.py:412` sync_all 端点 `assignees.like(f'%"{user.id}"%')`
   ——同 D-4 漏洞。照 D-4 修法：LIKE 前对 user.id 做 `.replace('%','').replace('_','')`（两行）
2. **card_discoveries id 幂等**（M-16，照 A-7 同修）：`CardDiscoveryReq`（data.py:33）加 `id: str = ""`；
   `add_card_discovery`（data.py:149）优先用客户端 id 并按 id 幂等去重，不再无条件 `id=f"disc_{timestamp}"` 覆盖

## 判据（验收方实跑）

1. 以含 `%` 的用户名调 sync_all → 不返回全量任务（curl 贴输出）
2. 同一 id 连续 POST 两次 card_discoveries → 库里只有一条（幂等）
3. 不带 id POST → 服务端正常生成 id（向后兼容）
