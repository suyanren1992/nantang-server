## D-1 冰箱内容显示不出

### 判：🔴 已定位——参数断链：写 inventory['info']、读 inventory['office']

### 全链勘察

| 环节 | 状态 | 详情 |
|------|:--:|------|
| 入口 | ✅ | 三条路径全可点击：全貌页管理卡片/快捷卡片/厨房房间详情 |
| 渲染 | ✅ | `renderKitchenPanel`(app.js:2294) 读 `inventory.office` 渲染双门冰箱 |
| 数据持久化 | ✅ | `inventory` 在 `_saveShared` 序列化清单中 |
| 数据写入 | 🔴 | **快捷面板路径写入了错误的空间键** |

### 根因

[app.js:2913](nantang-mobile/js/app.js#L2913) `_submitKitchenEntry`（快捷面板"放取物品"路径）：

```javascript
// 现状（缺第5参 spaceOverride）
_syncItemToAppData(action, sel.name,
  ((curBuilding()||{}).id === 'study' ? 'study' : 'office'),  // 第3参=location，但语义被曲解为spaceId
  true);  // 第4参=skipVerify，第5参缺失→undefined
```

函数签名 `_syncItemToAppData(action, itemName, location, skipVerify, spaceOverride)`：
- 第5参 `spaceOverride` 缺失 → `undefined`
- [app.js:2418](nantang-mobile/js/app.js#L2418)：`var spaceId = spaceOverride || (curBuilding()||{}).id || 'unknown'`
- 全貌页 `curBuilding().id === 'info'` → 物品写入 `inventory['info']`
- 但 `renderKitchenPanel` 只读 `inventory['office']` → 永远看不到

**对比正确路径**：[app.js:2409](nantang-mobile/js/app.js#L2409) `_submitKitchenLog`（面板表单路径）正确传了第5参 `'office'`。

### 触发条件

用户在**非 office/study 建筑页**（最常见是全貌页 info）通过快捷卡片"放取物品"提交物品 → 物品消失于渲染盲区。用户可能看到过期告警（`_getExpiryAlerts` 扫描所有键能找到），但打开冰箱空空如也。

### 修法建议（1行）

[app.js:2913](nantang-mobile/js/app.js#L2913) 补第5参：
```javascript
_syncItemToAppData(actionMap[act.action]||act.action, sel.name, '', true,
  ((curBuilding()||{}).id === 'study' ? 'study' : 'office'));
```

### 爆炸半径

🟡 中。影响快捷面板全部写入路径。已写入 `inventory['info']` 的幽灵物品需迁移（`init()` 中加一行合并回 `inventory['office']`）。

## D-2 住宿点房间闪

### 判：🔴 已定位——与 B-4 同类病症，不同交互点

### 调用链

```
_pickRoom / _openCheckinCard / _expandBed  [app.js:1663-1665]
  └─ _showStaySheet()                       [app.js:1498]
       └─ _showCardPopup()                  [app.js:1413]
            ├── old.remove()                ← 闪的第一帧（DOM消失）
            ├── el.innerHTML = ...          ← 整块重建（含<style>+房间网格+床位+日历）
            └── appendChild(el)             ← 闪的第二帧（DOM出现）
```

**每一次点房间、点床位、展开床位，都走这个全量 tear down → rebuild**。

### 闪的机制

```
old.remove() → [屏幕空白 ~1帧] → appendChild(newEl) + 样式重算 → 内容出现
     ↑                                    ↑
   消失帧                              出现帧 = 用户感知的「闪一下」
```

### 与 B-4 的区分

| | B-4 日历闪 | D-2 房间闪 |
|---|---|---|
| 触发 | `_calNav` 翻月 | `_pickRoom`/`_openCheckinCard`/`_expandBed` |
| DOM | `.cal-wrap` outerHTML | `.mgmt-sheet` remove+append |
| 根因 | outerHTML 暴力替换 | remove()+appendChild() 先删后建 |
| 病类 | **同一种**——DOM 整块替换导致瞬消瞬现 | |

### 附加发现

- **CSS 类名无碰撞**——B-7 修复后 `.stay-ci-*` 前缀已隔离
- **无重复渲染**——`refreshUserUI`/轮询/storage 事件均不触发住宿面板
- **Z-index 无冲突**——`.mgmt-sheet` z:260, `.stay-ci-overlay` z:9999
- **残留 bug**：`renderMgmtPanel('stay')` 一次调用产生两个面板（mgmtBody + 浮层卡片）

### 修法建议（参照 B-4 增量更新思路）

将选房间/开入住卡/展开床位改为 DOM 增量更新：
1. `_pickRoom` → 不调 `_showStaySheet`，仅更新 `.rm-card.active` + 替换 `.bp-panel` 内容
2. `_openCheckinCard` → 在 sheet 内追加 `.stay-ci-overlay`，不重建 sheet
3. `_expandBed` → 仅替换 `.bk-det` 详情区 DOM

## D-3 硬重置前端残留 P0 四症

### D-3a (🔴): localStorage 未清→401 风暴

#### 根因

**不是"忘了清某些 key"，是清完之后又写回去了。**

[core.js:1336-1351](nantang-mobile/js/core.js#L1336) `devReset()` 的时序：

```
API.devReset(mode) → 服务端删库成功
  → localStorage.clear()           // ✅ 全清
  → AppData.init()                  // ❌ 重新初始化！
    → _seedIfEmpty()                // 检测到数据空→填充种子
    → _saveShared()                 // 200ms debounce 写回 nt_app_v2_shared
  → setTimeout(reload, 800)         // 800ms 窗口
```

**800ms 窗口内**: `_saveShared` 已把种子数据（`nt_app_v2_shared` 含 6 间宿舍+5 块田地+3 个营地+配置）写回 localStorage。reload 后该 key 存在，但不含用户信息（`nt_session`/`nt_remembered_user` 已清且未重写）→ silentRefresh 返回 401（用户已删）→ 登录过期。

**多标签风暴**: Tab A 执行 reset → Tab B 的轮询/定时器仍用旧 token 发请求 → 每个 401 → silentRefresh → 401 → `_consecutiveFailures++` → 标记离线。

#### 修法

`core.js:1342` 在 `localStorage.clear()` 后：
- **删除** `AppData.init()` 调用（不回写种子）
- **加** `API.token = null; API.user = null;`（强制登出）
- 直接 `location.reload()`——reload 后 autoLogin→401→登录页，`AppData.init()` 在脚本正常加载中执行

#### 清键清单（19 个 key，`localStorage.clear()` 已全覆盖）

当前 `clear()` 已清全部 key，问题仅是回写 `nt_app_v2_shared`。无需补充清键列表，只需阻止回写。

### D-3b (🟡): buildings=0 时 _growDirtiness 崩

#### 分析

**正常路径安全**——双层防护：

1. [app.js:40](nantang-mobile/js/app.js#L40) `AppData.init()` 中 `if (typeof _growDirtiness === 'function')` 守卫——app.js 未加载时跳过
2. [app.js:29-36](nantang-mobile/js/app.js#L29) `getBuildings()` 有 `HARDCODED_BUILDINGS` 兜底——10 个建筑常量数组，永不空

`[Map] init failed` 来自 [app.js:2669](nantang-mobile/js/app.js#L2669) `_initMap()` 的 try/catch——任何子调用（`_growDirtiness`/`goTo(4)`/等）的异常都会被兜底。

**唯一危险路径**: app.js 脚本加载失败/解析中断 → `HARDCODED_BUILDINGS` 未定义 + `_growDirtiness` 未定义 → `AppData.init()` 中 typeof 检查为 false 跳过（安全）+ `_initMap()` 不存在不会被调用（安全）。结论：**不会崩，但地图页全白**。

**两案对比**：

| | 数据层兜底 | 渲染层兜底 |
|---|---|---|
| 做法 | `getBuildings()` 返回空时不崩 | `_initMap()` try/catch 兜底 |
| 优 | 静默降级，无异常 | 捕获一切 |
| 劣 | 用户看到空地图，不知原因 | toast "地图加载失败" 让用户知道出问题 |

**建议**: 当前防护已足够，不需加代码。若要加强，在 `getBuildings()` 返回空时 console.warn + toast 提示。

### D-3c (🟢): 旧校核 ID→404 无本地清理

#### 分析

**正常路径安全**:
1. `localStorage.clear()` → 清空 `pendingVerifications`（在 `nt_app_v2_shared` 中）
2. `AppData.init()`（reload 后正常执行）→ `_data.pendingVerifications = []`
3. `syncAll` → 服务端 `verifications: []` → 本地保持 `[]`

**唯一边缘风险**: 多标签场景——Tab B 在 Tab A reload 前离线创建了新的 `pendingVerifications`（仅存 localStorage）。Tab A reload 后 Tab B 的 storage 事件触发同步，将旧 ID 写入了新标签页的 `nt_app_v2_shared`。

**不存在定时清理逻辑**: `_archiveOldDiscoveries` 只管 discoveries，不管 pendingVerifications。没有 cleanup/purge 函数。

**建议**: 在 `devReset()` 中 `localStorage.clear()` 后加 200ms 的 `sessionStorage` 标记 `_dev_reset_pending`，`AppData.init()` 检测到该标记时跳过 `_saveShared()` 的第一次调用。

---

### D-3d (🟢): 登录态残留→switchUser 到已删用户

#### 分析

**正常流程安全**:
1. `localStorage.clear()` → 清 `nt_session`/`nt_remembered_user`/`nt_local_users`/`nt_local_roles`
2. `location.reload()` → autoLogin → `silentRefresh` → 401 → 登录页
3. 登录页调 `/api/auth/users` → 服务端返回空 → 显示"还没有账号"

**不会 switchUser 到已删用户**——`silentRefresh` 返回 401 后 `API.token = null`，不会进入 `switchUser` 路径。

**唯一边际风险**: 多标签 storage 事件在 800ms 窗口内将旧 `nt_local_users` 数据写入新标签页。

**建议**: 与 D-3a 合并修复——`localStorage.clear()` 后直接 reload，不加 `AppData.init()`。

### D-3 修法汇总

**核心接线点**: [core.js:1336-1351](nantang-mobile/js/core.js#L1336) `devReset()` 函数

```javascript
// 修改前（line 1342-1347）
localStorage.clear();
if (window.NT) NT._reset();
if (window.AppData) { AppData._data = {}; AppData._currentUser = ''; AppData.init(); }
showToast('...');
setTimeout(function(){ location.reload(); }, 800);

// 修改后
localStorage.clear();
sessionStorage.setItem('_dev_reset_pending', '1');  // 防多标签storage回写
if (window.NT) NT._reset();
if (typeof API !== 'undefined') { API.token = null; API.user = null; }
showToast('已重置，即将刷新...');
location.reload();  // 立即刷新，不 debounce
```

同时在 `AppData.init()` ([app-data.js:37](nantang-mobile/js/app-data.js#L37)) `_seedIfEmpty()` 前加：
```javascript
if (sessionStorage.getItem('_dev_reset_pending')) {
  sessionStorage.removeItem('_dev_reset_pending');
  return;  // 跳过种子填充+_saveShared 回写
}
```

**爆炸半径**: 🟢 低。仅改 `devReset()` 一条函数的时序，不碰业务逻辑。

## D-4 田间交互对焦

### 判：🟡 差距清单——三条入口互不协调+2/4提交函数不接校核+定价分裂

### 现状：三条并行入口

| 入口 | 位置 | 流程 |
|------|------|------|
| 地图建筑页 | [app.js:930](nantang-mobile/js/app.js#L930) | 点田块卡片→`buildFieldDetail`→"+记录农活"→`_openFarmQuick` |
| 全貌页卡片 | [app.js:358](nantang-mobile/js/app.js#L358) | `_openMgmtSheet('field')`→`_showFieldSheet`弹窗→"+记录农活"→`_openFarmQuick` |

### 差距清单

| 步骤 | 现状 | 期望 | 差距 |
|------|------|------|------|
| **选田块** | `_showFieldSheet` 点 plot→关闭弹窗+跳转地图页，非停留选择；不显示子区域 zones | 点击田块→停留选择劳动 | 点击行为打断预期流程；三条路径 UI 各独立渲染 |
| **选劳动** | 不存在独立步骤。`_openFarmQuick` 将动作+田块并排放置，仅 6 种动作（收割/浇水/种植/施肥/除草/查看），缺翻土/搭架/防虫/覆盖/修剪 | 分步：选田块→看到可选农活列表（含NT奖励）→选择劳动 | 非分步流程；动作不全；无季节过滤 |
| **提交校核** | 4 个提交函数中仅 2 个接 `addVerification`：`_submitFarmEntry`✅ + `_harvestCrop`✅；管理面板的 `_submitFieldLog`❌ 和 `_submitFieldPlant`❌ 只写本地 history 不接校核 | 全部路径走校核，含 NT 奖励+证据照片 | 管理面板农活=假数据（无NT、无校核记录） |
| **NT定价** | 两套定价并存：`farming_pricing`(app.js:51) 和 `labor_pricing`(app.js:69)。fertilize: 5 vs 15NT, weed: 5 vs 15NT | 统一用 `labor_pricing`（公约权威来源） | 定价分裂，快速面板取低价(farming) |
| **数据持久化** | `_submitFarmEntry` 走校核但不更新 plot 状态（浇水后remain不变、收割后crop不清空）；`_harvestCrop` 是唯一同时改plot+校核的函数 | 校核通过后 plot 状态同步更新 | plot 状态与校核脱节 |
