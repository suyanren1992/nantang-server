## 施工内容（三件套，缺一不可）

1. **提案入口**：公约 overlay（app.js:316-346 `_openCovenantOverlay`）加「修改提案」按钮（仅管理员可见）
   → 调 `proposeConfigChange`（app-data.js:506-523，已存在）
2. **待校核展示**：`pendingConfigChanges` 非空时在公约 overlay 渲染待校核列表 + 校核按钮
   （需 2 人确认、提案者不能自校）→ 调 `verifyConfigChange`（app-data.js:525-561，已存在）
3. **服务端同步**：sync_shared 接 `pendingConfigChanges`/`configHistory` 两字段
   （复用 MapLocation，key="config_changes"/"config_history"，照 D-12 presence 修法）

## 铁律

- 凡改 js 同 commit 升 index.html `?v=`；只 commit 不 push
- UI 风格照现有 overlay，不新造组件体系

## 判据（验收方实跑）

1. 管理员账号发起一条定价修改提案 → 服务端 sync_shared 有 config_changes 记录
2. 另两个账号（非提案者）各点校核 → config 自动 apply + configHistory 落一条
3. 公约 overlay「📝 修改记录」段渲染出该条历史
4. 换设备/清缓存重登 → 待校核列表与历史仍在（服务端权威）
