### 太傅注：为什么缓存版本号是移动端 Web 的命门

移动端 Web（特别是 PWA / 添加到主屏幕的场景）有一个经典的「修好了但用户看不到」问题：

**浏览器缓存铁律**：浏览器对 `<script src="foo.js">` 的默认策略是「只要 URL 相同，就用本地缓存，不发网络请求」。这意味着你在服务端更新了 `foo.js`，但已访问过的用户浏览器里运行的还是旧版——直到缓存过期（可能几天甚至几周）。

**`?v=` 就是手动过期钥匙**：`foo.js?v=16` → `foo.js?v=17` 在浏览器眼里是**两个不同的 URL**，缓存不命中，强制拉新版本。这是最简单也最可靠的缓存破坏（cache busting）手段——不需要改 nginx 配置，不需要 Service Worker 逻辑，一行字符解决。

**为什么南塘云村尤其致命**：
1. 前端是**单文件静态站**（`index.html` + 一堆 JS）——没有 Webpack/Vite 的内容哈希自动注入，全靠人工维护 `?v=`
2. 用户把页面**添加到手机主屏幕**后，浏览器对 PWA 的缓存比普通网页更激进
3. 后端 API 改了字段名、前端 JS 同步更新——但如果用户跑的是旧版 JS，调新 API 直接报错，**体验上就是「App 崩了」**
4. 历史上已踩过两次坑（`CLAUDE.md` 铁律第 2 条就是血的教训）

**一句话**：改 JS/CSS 不升 `?v=` = 修了等于没修。这 6 个文件之前漏标，意味着它们在过去任何一次修改中，已访问用户都拿不到新版本。这次补齐，等于给缓存铁律补上了最后一颗牙。
