# G-3 住宿费改「每日记账+退房总结账」（二营 · 跨端大卡）🔴

> 来源：砚仁 2026-07-28 谕（每日扣款只是记账，退房时总结账更好）+
> 《社区公约 v12》4.2（结房费时一次性付）+ 对照清单第四节冲突警示 +
> DB-1 风险（住宿欠费无上限无追缴）
> 施工：豆包 Codex（二营，跨端全权可动前端）｜验收：Claude Code（一营）
> 排期：G-1 交卷后开工（钱流大卡，不与签署域混排）
> 议定三配套（砚仁 19:02 准）：记账可见 · 7 天提醒/14 天限预定 · 退房一次性结算

## 施工内容（四件）

1. **日扣改日记账**：住宿每日自动扣 nt_balance 改为**应计记账**——
   `accommodation_due` 累计字段（或 accrual 流水类型），每日 +房费，不动 nt_balance；
   原日扣逻辑保留代码但切到记账分支（回滚可逆）。
2. **退房一次性结算**：退房时汇总 `accommodation_due` → nt_balance 够则一次性扣
   （ledger 流水 + pool 同步）→ 不足部分记欠费（debt 字段，明示）；结算单展示
   「住了 X 天 · 每天 Y · 合计 Z · 已付/欠费」。
3. **欠费上限规则**：记账累计超 7 天房费 → 用户可见提醒（🔴钱动必出声）；
   超 14 天 → 限制新预定（拒绝必出声给原因）。天数进 config 不硬编码。
4. **记账可见**：前端住宿/工作台显著位置显示「已记账 X NT（退房时结算）」；
   欠费状态醒目提示。

## 爆炸半径（四答）
- 改几个文件：server（models/住宿逻辑/退房端点/测试）+ 前端（住宿卡/工作台显示）——大卡，逐文件列回执
- 影响功能：**钱流主线变更**——住宿计费全链路；提现/校核/任务托管不动
- 破坏性变更：有——日扣停扣改为记账，存量欠费/余额的迁移策略必须在施工方案里写明
  （存量已扣的不回滚；存量欠费并入 due 继续记）
- 回滚：记账分支可切回日扣（代码保留）；已结算流水不可逆，回执须写清

## 铁律
- **禁区**：withdraw / confirm / reject 资金端点零改动（丞相闸口必查）
- 钱随单走：每笔结算必 ledger 流水 + 对账等式不破（nt.py:395 校验必过）
- 只 commit 不 push；只加具名文件；pytest 零回归+新增记账/结算/上限测试
- 回执独立落盘 `方案/任务卡/` 随 commit；末尾太傅注三行内

## 判据（验收方实跑贴输出）
1. 入住 3 天 → nt_balance 不变、due 累计 3 天房费、前端可见「已记账 X NT」
2. 退房（余额够）→ 一次性扣款 + ledger 一条 + 结算单展示 + due 清零
3. 退房（余额不足）→ 实扣部分 + 欠费明示 + 欠费入账
4. due 超 7 天 → 提醒；超 14 天 → 新预定被拒且人话提示
5. 对账等式（nt.py:395）全场景通过；pytest 零回归
