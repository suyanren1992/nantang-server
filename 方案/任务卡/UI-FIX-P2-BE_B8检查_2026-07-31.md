## 结论

**端点存在，但有两处差异：**

1. **缺 `task_id` 字段**：Verification 模型无 task_id 列。task 关联靠 `detail` JSON 中的 `clean_weekly_task_id`（CLEAN-WEEKLY-BE）或 NTTask 的 `evidence`/`task_id` 间接查。
2. **`verifier_id` → `verifier`**：字段名不同但含义一致。FE 适配时需注意映射。

## 建议

- **FE 适配（不改 BE）**：`verifier` 字段映射为 `verifier_id`；`task_id` 从 `detail` JSON 中提取（如果有）。
- **BE 补强（需新立卡）**：若需独立 `task_id` 字段，给 Verification 模型加列 + 回填。

**是否需要新立卡：⚠️ 视 FE 需求**
- 如 FE 可接受从 `detail` JSON 提取 → 不需新卡
- 如需顶层 `task_id` 字段 → 需新立卡
