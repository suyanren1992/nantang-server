## 3. D-4 方案 A ✅

### 问题
旧方案 `replace('_', '')` 删除下划线 → 含 `_` 合法用户名（如 `user_name`）在 LIKE 查询时丢字 → 对不上 JSON 中的 `"user_name"` → 看不到自己的任务。

### 方案 A：剔除 → 转义

三处 `server/routes/` 统一改造：
```python
# 旧（删除，破坏数据）
uid = user.id.replace('%', '').replace('_', '')

# 新（转义，LIKE 将 \% \_ 视为字面字符）
uid = user.id.replace('%', r'\%').replace('_', r'\_')
```

同时在 `.like()` 加显式 `escape='\\'`（SQLite 无默认 ESCAPE 字符，PostgreSQL 默认 `\`，显式声明双兼容）。

## 太傅注（三行）

- **转义 vs 删除**：`replace('_', '')` 是破坏性操作，删了用户名的字；`replace('_', r'\_')` 是告诉 LIKE「这个下划线是字面字符，不是通配符」——不改数据，只改语义。补课：SQL LIKE 的 `%` 和 `_` 是元字符，清洗输入时转义 > 剔除。
- **SQLite LIKE 无默认 ESCAPE**：PostgreSQL 默认 `\` 作 LIKE 转义符，SQLite 没有默认值。不加 `escape='\\'`，SQLite 上 `\_` 仍是通配符——测试会过不了。适配双数据库是宪法的 K-2 级要求。
- **一营越阵地原则**：正常一营不碰 `server/`，本批第 3 条是丞相/砚仁亲批越界，派工单 > CLAUDE.md。下次越阵地施工同样须派工单明文授权。
