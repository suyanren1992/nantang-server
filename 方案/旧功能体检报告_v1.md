### A-1 · `closeOverlay` 参数名遮蔽全局函数 → 每次关弹层都报错

- **文件:行号**：`nantang-mobile/js/data.js:699-706` + `nantang-mobile/js/core.js:2041`
- **触达方式**：任意 overlay 关闭时（点击 ✕ / 返回 / 遮罩）
- **错误表现**：Console 报 `Uncaught TypeError: showVillage is not a function`
- **根因**：`function closeOverlay(id, showVillage)` 的参数名 `showVillage` 遮蔽了全局函数 `showVillage()`（定义在 `core.js:2041`），第 706 行 `showVillage()` 实际调用的是 `undefined` 参数
- **严重度**：🔴 Critical — 影响所有弹层关闭后的页面跳转
- **修复建议**：参数改名 `closeOverlay(id, returnToVillage)` 或将全局函数挂 `window.showVillage`

### A-3 · 任务大厅"认领"按钮无响应

- **文件:行号**：`nantang-mobile/js/data.js:380-402`（`claimTask`）+ `nantang-mobile/js/core.js:338-460`（`openQuestHallPage` / `renderTaskCard`）
- **触达方式**：首页 → 任务大厅 → 点击任意任务"🎯认领"按钮
- **错误表现**：点击"🎯认领"后无任何 UI 反馈
- **根因分析**：
  1. `core.js:360` 从 API 同步任务到 `AppData._data.tasks[t.id]`，但任务不包含 `name` 字段（使用 `title`）
  2. `data.js:11` `TASKS` 指向 `AppData._data.tasks`，但 `claimTask` 用 `name` 键查找
  3. 任务大厅渲染的任务来自 `core.js:338` 的 `filterQuests`/`renderMyTasks`，可能和 `TASKS` 不是同一数据源
  4. 加上 A-2 的服务端路由缺失，任务 accept 端点也走不到
- **严重度**：🔴 Critical — 核心交互链路断裂
- **修复建议**：统一任务数据键名（`name` vs `title` vs `id`）+ 重启服务器加载任务路由

**太傅注**
- 补课：**部署 ≠ 提交代码**。`main.py:110-126` 的 `include_router` 写了 16 行，但服务器运行的还是旧进程。改了代码不重启 = 没改。A-2 是这个教训的教科书案例——一行 `uvicorn` restart 就能修 26 个 404，但它藏在整个系统深处，从 UI 上看就是"共享厨房打不开""通知收不到""提案交不了"。
- 一句原理：**永远先查环境再查代码**。这次 36 条问题里，P0 最严重的一条（A-2）不是逻辑 bug，是运行环境滞后——服务器没重启。
- 不这样做会怎样：继续在 46% 的 API 都 404 的系统上开发新功能——每张新卡依赖 404 端点时，都以为"后端已就绪"，实际全线不通。
