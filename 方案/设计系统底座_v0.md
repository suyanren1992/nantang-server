# 🎨 南塘设计系统底座 v0

> 用途：所有页面设计的"引用真源"——后续每张页设计稿都从此底座引组件/引令牌，禁自造。
> 路线：**对齐≠创造**（手册§〇）。90% 内容引用已上线的勘察/真仓 CSS/已有范式，不重造。

---

## 〇、最高原则（与手册同步）

- **少点几步 = 头等 UX 指标**（皇帝 2026-07-30 拍板）
  - 所有高频操作 → 工作台快捷抽屉入口
  - 一页做完的事，绝不拆两页
- **复用 > 创造**：底座里有现成组件 → 直接引；没有 → 先看范式族 → 仍无 → 才新造并入底座
- **风格统一优先于个人审美**：令牌/组件/范式三件套对齐 > 单页好看

## 三、交互范式（Interaction Patterns）· 横切组件的"用法模板"

> 范式 = 把多个组件按"用户做某事"的方式拼起来。各页设计稿**引范式**而非自己拼流程。

### A·劳动流（选对象→选劳动→提交→校核）—— 首批重点

**适用**：田间管理 / 大扫除 / animal_care / 厨房录入

**流程组件拼装**：
```
[对象选择(地图/网格/卡片)]
   ↓
[动作选择(动作卡/价签)]
   ↓
[提交] → 走 /api/data/verifications(服务端统一入口,三客户端入口)
   ↓
[校核人确认] → 走服务端定价+校验
   ↓
[结算] → 单一真源定价表 → NT
```

**🔴 现状硬伤**（来自 W6-RECON 勘察）：
- 定价 4+3 套分裂（同一除草 5NT vs 15NT）
- 客户端传 nt_amount，服务端不校验
- `/api/nt/earn-sync` 绕过校核后门

**🛠 改造点（涉钱，列皇帝御笔）**：
1. 服务端建定价单一真源（`MapLocation` config 或硬编码表）
2. verifications 写入时校验 `nt_amount ∈ 合理范围`
3. `/api/nt/earn-sync` 加 admin 鉴权 + 与 verification 关联

### B·社区通件（列表+卡片+详情+交易）—— 同步出稿

**适用**：茶馆八卦 / 二手集市 / 拍卖会 / 共享厨房接龙 / 宿舍订餐

**流程组件拼装**：
```
[条目流(列表/卡片)]
   ↓
[详情(模态)]
   ↓
[交易(提交/竞价/接龙/订)]
   ↓
[结算走 /api/nt/transfer(单一交易端点)]
```

**🔴 现状硬伤**（来自 W6-RECON-B 勘察）：
- 茶馆/拍卖：**零代码**
- 集市：前端本地翻 status，不落服务端
- 订餐：POST **只录入不扣钱**（C-4 陷阱：NT 已扣订单消失）
- sync_all 漏 meal_orders

**🛠 改造点**：
1. 集市上架/下架/成交补服务端状态机
2. 订餐后端加确权扣费（防丢单）
3. sync_all 补 meal_orders
4. 茶馆/拍卖——**功能新建**，先打 NT 交易端点骨架，再上 UI

### C·议事共建（提案+投票+签署）—— 后批

**适用**：议事厅 F18 / 营地提案区 / 公约签约 UX

**流程组件拼装**：
```
[提案(富文本)]
   ↓
[公示(列表+留言)]
   ↓
[投票(投票条)]
   ↓
[通过 → 走签署(动画全屏 UX)]
```

**待造组件**：投票条、签署动画。

### D·引导流（任务清单+打勾+校核）—— 后批

**适用**：新人引导（现实任务清单）

**流程组件拼装**：
```
[引导任务列表(步骤清单)]
   ↓
[真做(各 A/B 范式)]
   ↓
[找校核人(双向打勾)]
   ↓
[双向发 NT]
```

**与"用户引导"区别**（皇帝 2026-07-30 拍板）：
- **新人引导** = 现实任务清单（认地方→认人→认物），走本范式，可进工作台
- **用户引导** = 游戏式界面导览（小人+对话气泡+spotlight 高亮"点这点那"），**独立浮层**，**不进工作台**——另立"引导浮层范式"，首批后另议

### E·楚门展示层（共用 interactions 表）—— 后批

**适用**：南塘此刻弹幕 / 在地 NPC 渲染（已 W6-P-FE 落地）/ 在地翻牌三态（已 W6-P-FE 落地）/ 日志分类 / 人员档案 / 档案室内容

**底层**：`interactions(target_type, target_id, user, type, content, nt_amount)` 通用表
**接口**：`/api/interactions` CRUD + `/api/interactions/stream` 拉新

### F·UI 焕新（图标/赞赏样式）—— 独立项

**适用**：赞赏样式升级 / 活动窗口样式 / 图标现代化
**做法**：本底座**不强制**——若 F 立项单独立项出设计稿

### H·工作台快捷抽屉（新立 · 皇帝 2026-07-30 拍板）—— 首批重点

**适用**：所有高频操作都该有工作台快捷入口（"少点几步"总则具体化）

**形态**：
```
[工作台内右下角 ⚡图标]
   ↓
[点击 → 抽屉从底部滑入(W6-UI 已落地 slideUp 模式)]
   ↓
[按身份动态显示条目]
   · 在地伙伴/NPC → 厨房快捷录入
   · 营地共建人 → 营地快捷操作
   · 其他人 → 默认空态"暂无快捷"
   ↓
[点击条目 → 直接执行,不绕全貌页]
```

**首批内容**：厨房录入（接入 A 劳动流）+ 营地操作（接入营地相关）。
**后续**：用户引导入口、设置入口、提现入口（"少点几步"原则下都该进抽屉）

## 五、底座使用规范（皇帝批后即生效）

1. **每张页设计稿必带"底座引用清单"**：
   ```
   本稿引用：令牌 [色1,色2,字1,间距1,圆角1]
            组件 [按钮-主,卡片-内容,抽屉-底部,状态牌]
            范式 [A劳动流, H工作台快捷抽屉]
   ```
2. **不许自造**：无引用清单的设计稿 = 不合规，退回。
3. **新造即入底座**：设计稿中确实需要新组件/新令牌 → 写"底座新增条目"+ 卡片代码位置 → 批准后入底座。
4. **底座 v0.1 触发条件**：累积 ≥3 处令牌/组件补入 → 升 v0.1。
