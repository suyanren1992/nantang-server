# 丞相省 Token 操作规范（新官上任 · Codex 立）

> 立规缘由：前两任丞相（Kimi Work、Qoder）都很快烧完 token。经诊断，**审计比施工结构性更耗 token**（吞证据做判断、常驻会话上下文滚雪球、反复核真源）。其中"固有成本"消不掉，但"工作流浪费"能省一大半。本规范把省下来的部分固化成纪律。

## 一、为什么审计更耗（认清才好省）
1. 施工是"窄而深"（边界清、改完即走）；审计是"宽而杂"（每卡都要吞 pytest/diff/契约一大堆输出）。
2. 长输出反复进上下文 = token 黑洞（一次全量 pytest 的 warning 就上千 token）。
3. 上下文只增不减，丞相是常驻角色 → 同会话越到后面每轮越贵（雪球）。
4. "制卡前必亲证"要反复 grep+读真仓。
**→ 施工是脉冲式，审计是持续高位。同预算下丞相烧得快是必然，但工作流可优化。**

## 二、🟢 低成本纪律（立刻执行，省一大半）
1. **工具输出一律截尾**：
   - pytest：`... -q -p no:cacheprovider 2>&1 | Select-Object -Last 5`，只认最后汇总行（`X passed`）+ 失败详情。绿了只回一行"PASS: 136 passed"。
   - node --check / deploy_check：只取 exit code + 尾行，绿了记"PASS"，不复述全文。
   - git show：已只给 diff，**只读改动 hunk，不重读整文件**。
2. **禁止把整份长输出灌进上下文**——警告用 `2>&1 | Select -Last N` 或 `-p no:warnings` 压掉。
3. **回执逐条对时引用行号，不整段复制粘贴**。
4. **报到/回话简短**：状态用表格/一行，不铺陈。

## 三、🟡 中成本结构（改工作流）
5. **一卡一会话**（最关键）：每张卡验收开新会话，验完写回 BUG_TRACKER + 总账就结束，**不让上下文滚雪球**。前任烧完多半死在"一个会话验一整天"。
6. **分工分模型**（宪法第八条"便宜模型能干的不上旗舰"）：跑测试、grep、格式检查等机械活交便宜窗口/脚本；丞相只做需判断的部分（守恒判据、契约冲突、药方对不对）。
7. **判据脚本化**：能固化的验收判据（涉钱守恒 total_system、前后端字段对照）写成一次性脚本跑，**输出只回一个结论**，不占对话。deploy_check.py 就是范例，继续扩。

## 四、🔴 制度层（砚仁掌）
8. **丞相设 token 预算 + 分批交接**：验完一批主动写留痕、换窗，**主动交接比烧到断更安全**（交接包"你也会被换，判断留痕在文件里"即为此设计）。
9. 预算将尽时：先落总账、更新在途快照，再交接，绝不悬空。

## 五、单卡验收标准动作（省 token 版）
```
# 1 对状态（一次，尾部即可）
git log --oneline -3
git show <hash> --stat            # 只看 stat + 关键 hunk
# 2 跑测（只认尾行）
cd server; $env:JWT_SECRET='test-secret-key-for-ci-32bytes-long'
..\.venv\Scripts\python.exe -m pytest tests/ -q -p no:cacheprovider 2>&1 | Select-Object -Last 5
# 3 前端改动（若有）
node --check js/<file>            # 只认 exit code
# 4 契约字段：引用行号逐字对，不贴整段
```
**判据不符即打回写明理由；符合则一行副署："PASS <卡号>，X passed，字段对齐"。**

## 六、一句话总结
审计固有成本消不掉（吞证据做判断），但**截尾输出 + 一卡一会话 + 判据脚本化 + 便宜模型分担机械活** = 把前任烧掉的"工作流浪费"省回来。**丞相的 token 要花在判断上，不是花在复述工具输出上。**
