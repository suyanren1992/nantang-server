# 丞相读书笔记

> 规则：每篇三行——①讲了什么 ②我们做到没 ③差距与处置。读完一批追记一批。

## 10.1 立项（2026-07-26 读）

- **讲了什么**：先讨论后写码；立项八要素（面向谁/边界/路径/对象/技术路线/爆点/里程碑/验收）；文档是真源。
- **我们做到没**：✅ 全做到。立项文档 v2 八要素齐，还多出三足鼎立+历史基因。
- **差距**：无。教程 A 级。

## 10.2 功能清单与阶段拆分（2026-07-26 读）

- **讲了什么**：功能三拆法（角色/流程/模块）；复杂功能单独成篇+清单留索引；大阶段判据=某类用户完整跑通一条核心流程；文档一条线引用。
- **我们做到没**：拆分与引用链 ✅；大阶段判据 ✅（批①②③划分合此精神）。
- **差距**：①**复杂功能未拆单篇**——F2 任务流转/F3 NT 经济/F4 住宿结算应各拆一份（入作战图谏言箱）；
  ②**dev-docs 推远程分歧**——教程建议内部资料不推远程，我们全推了（有意识的路线分歧：Render 同仓+多 AI 协作，需记决策依据）。

## 11 技术栈（2026-07-26 读）

- **讲了什么**：产品形态定技术栈；成熟框架优先（框架=现成规范，专治 AI 自由发挥）；让 AI 给**唯一推荐**而非选择题；技术栈必写进文档，含「不用什么」与「何时重新评估」。
- **我们做到没**：选型事实正确（PWA/原生 JS/FastAPI/Neon PG/Render——全是成熟轮子，符合"克制"原则）；但从未写下为什么。
- **差距**：③技术栈文档卡**加两条硬要求**——「不用什么（React/Vue/小程序等）及理由」+「重新评估触发条件」。教程 A 级。

## 4.1 Agent 宪法（2026-07-26 读）

- **讲了什么**：宪法六模块——身份定位/底层红线/编码规范/执行规则/输出规范/自查三重；宪法≠需求文档≠阶段真元文档，三件套各司其职。
- **我们做到没**：一门三规+CLAUDE.md/AGENTS.md+施工流程覆盖模块 1/2/4/6（身份/红线/执行/自查），且我们的朝会修订程序优于教程的"宪法不变"；三件套映射成立（宪法=总则+施工流程，总需求=立项+功能清单，阶段真元=任务卡）。
- **差距**：①**模块 3「统一编码规范」全缺**——代码层命名/注释/异常处理统一格式从未立（现有风格指南只管 vault 文档层）；
  ②模块 5 输出规范部分覆盖（回执/太傅注），但代码输出格式（先述思路、标注路径、拆段）未明文化。
  处置：入作战图谏言箱，批②宪法汇编指针页时一并补「编码规范」一节。

## 13 前端骨架（2026-07-26 读）

- **讲了什么**：先定设计风格→框架/组件库（框架管结构，组件库管界面）→目录/模块/组件复用
  （同类 UI 出现 >2 次必须抽象）→设计 Token 先行→只搭骨架不贪页面。
- **我们做到没**：目录/模块边界 ✅（E-1 实证九模块清晰、双轨已清）；
  原生 JS 无框架无组件库=有意识路线分歧（立项文档已写明：轻量/无构建/AI 友好），教程也承认
  "不用框架能做好，但主要靠 AI 写前端时强烈建议成熟方案"——分歧合理但代价要自己扛。
- **差距**：①**DESIGN.md 设计 Token 已文档化但未接入代码**（功能清单 F6 实证）——教程红线
  「所有颜色字号间距必须从 Token 取，不许硬编码」我们恰好破着；②组件复用规则未立，
  ui-* 模块间有无重复 UI 未审。处置：入谏言箱，批②④架构文档立「Token 接入+组件复用」规则。

## 16 后端骨架（2026-07-26 读）

- **讲了什么**：架构设计文档必含 11 项（语言框架选择原因/工程规范/框架最佳实践/框架最大化利用/
  目录约束/接口响应规则/错误处理/日志/数据库连接/权限入口/新增模块规则），再根据文档搭
  最小骨架四线（启动/接口/业务/运维）。
- **我们做到没**：FastAPI 路由分组 ✅、环境变量检查 ✅（deploy_check）、权限校验 ✅（D 系列后）；
  骨架本身早已存在（项目是先盖楼后补图纸）。
- **差距**：11 项 checklist 中**统一错误处理、日志规则、接口响应格式**三项从未成文——
  D-7 任务状态 400 静默失败正是"错误处理无统一规则"的活例。处置：11 项直接作为
  ④架构设计文档卡的验收 checklist（与技术栈文档「不用什么+重新评估条件」合并发卡）。

## 14 数据库设计（2026-07-26 读）

- **讲了什么**：从业务找对象→确认关系（1:1/1:N/M:N）→选库→三范式校验→字段规范
  （英文下划线/created_at/updated_at/软删除 deleted_at/密码 hash/金额整数分不用浮点）→
  **schema/migration 文件先入 Git 再建表**——结构变更永远先改文件再执行。
- **我们做到没**：业务对象已盘点 ✅（功能清单§七九对象对应表）；Neon PG+SQLite 双轨 ✅ 符合教程。
- **差距**：①**无 migration/schema 快照体系**——表结构怎么变更的、怎么管的，没有文件约束，
  教程铁律「结构变更先改 schema/migration 再说原因」我们无此闸；②金额字段存储方式未审
  （NT 是整数还是浮点？）；③软删除未用。处置：批②数据库设计补文档加两条——
  schema 快照入 git + 金额/软删除/状态字段规范审计。

## 17 后端验收（2026-07-26 读）

- **讲了什么**：验收靠**规则+示例+证据**，不靠读代码。目录责任表（职责/应放/禁放/框架或自定义）→
  最小模块演练→**接口响应 11 场景示例**（列表/详情/创建/更新/删除/空列表/参数错/未登录/
  无权限/不存在/系统异常）→框架复用边界→运行证据包→收口成「实施真源文档」，
  宪法只引用不臃肿。**没证据=未验收，不许"基本完成"。**
- **我们做到没**：交叉验收制+变异抽查已超过教程深度 ✅；「没证据不写通过」=铁律 5 口说无凭 ✅；
  运行证据包=deploy_check 部分覆盖 ✅。
- **差距**：**接口响应 11 场景示例从未做过**——D-7 静默 400 正是代价。处置：④架构设计文档
  =教程的「实施真源文档」，内容=16 篇 11 项 + 17 篇接口 11 场景示例 + 目录责任表
  （E-1 已有一半）；宪法汇编页只写引用条款不写细则——与砚仁「不新立条款」谕完全一致。
